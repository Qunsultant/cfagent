## Survey correction — two facts in comment 6769094676 were wrong, plus Public MCP schemas verified

**Correction 1 — Alpaca fundamentals: declared, but not servable.**
The survey's matrix listed Alpaca as declaring `quotes + historicalBars + fundamentals`, which is what `adapters.ts` declares via the shared wrapper. Verified deeper: `AlpacaMarketDataProvider.getFundamentals` **throws** (`src/services/marketDataResearch.ts:2454-2458` — "Alpaca has no live fundamentals source in this codebase — fail explicit rather than serving the profile. Use the Yahoo provider"). The registry's servability is declaration-based (registry.ts: an adapter is servable when it declares the capability), so the declaration is misleading: a fundamentals call routed to Alpaca primary fails explicitly instead of gap-filling. The conformance kit states the rule (conformance.ts:23-24): "A provider that declares a capability it does not implement fails that capability's check" — declared must equal servable. The fix therefore drops `fundamentals` from the Alpaca adapter's declared capabilities; fundamentals stay routed to Yahoo (default route `fundamentals → yahoo`, providerConfigPorts.ts:182; ADR 0019: "Alpaca fundamentals are Yahoo-covered, never faked"). Corrected Alpaca row: serves `quotes + historicalBars + optionsChains` (new); fundamentals via the Yahoo route. Yahoo serves `quotes + historicalBars + fundamentals + news` (#3932).

**Correction 2 — public seed staleness.**
`providerConfigPorts.ts` seeds public as "a descriptor only — 'registered', no adapter until its integration slice". The data adapter now exists and is registered AVAILABLE (dataProviders.ts #1247), but servability still gates on the config store's lifecycle state — public serves nothing until an operator configures → verifies → enables it. Consequence: "screening on Public" needs the public provider record enabled (an operator lifecycle act, P4), not just code. Recorded here so the §15 report can state the activation step.

**Public MCP trading tools — verified against Public's official docs** (research 2026-11-10; sources: official server README github.com/PublicDotCom/publicdotcom-mcp-server, official SDK README publicdotcom-py, hosted-MCP docs public.com/api/docs/templates/hosted-mcp, API FAQ public.com/api/docs/faq, Glama live-inspected schemas of the official server v0.3.1–v0.9.0):
- 11 write tools confirmed: `place_order` (single-leg stock/crypto/options; bracket via `order_class` BRACKET/OCO/OTO + `take_profit_limit_price` / `stop_loss_stop_price` / `stop_loss_limit_price`; prices are decimal strings; whole-share quantity for brackets), `place_multileg_order` (legs + quantity + signed limit_price, max 6 legs), 4 spread helpers, `place_short_order`, `buy_event_contract`, `flatten_and_go_short` (experimental, NOT atomic), `cancel_order` (idempotent), `cancel_and_replace_order`.
- Reads: `get_portfolio` (positions, buying power, open orders; non-IRA only), `get_orders`, `get_order` (order_id required; last 30 days only), `search_orders` (≤500), `get_option_greek` / `get_option_greeks` (OSI symbols; greek fields can be null — guard).
- Preflight (8 tools): `preflight_order`, `preflight_multileg_order`, `preflight_short_order`, 4 spread preflights, `preflight_buy_event_contract` — validate + estimate fees/buying-power without placing. Preflight is NOT a guarantee ("Some checks only run at placement").
- Auth: OAuth scopes `trading.read`, `trading.write`, `marketdata`, `openid` (trading needs `trading.write`); a personal access token works for trading as Bearer (key → access token exchange, 5–1440 min validity).
- **No paper mode — confirmed twice in official docs**: "Placing a trade through any MCP client is a real order using real money in your Public account." No sandbox/dry-run flag exists. Adapter tests use preflights + fakes/mocks only.
- Placement is async: `place_order` returns an order ID (acceptance receipt, NOT a fill); poll `get_order` (tolerate a 1–2 s 404 indexing window). Statuses: NEW, PARTIALLY_FILLED, FILLED, CANCELLED, QUEUED_CANCELLED, PENDING_CANCEL, PENDING_REPLACE, REPLACED, REJECTED, EXPIRED (CANCELLED double-L). Rate limit 10 req/s per account (429 → backoff). MCP `place_order` exposes NO idempotency-key argument — the adapter must guard retries itself and verify via `get_order`/`search_orders` before retrying, or risk a duplicate real order.
- Still unverified: hosted-vs-local tool parity (needs one live `tools/list` against https://mcp.public.com/mcp at integration time); MCP-level arg names for the spread helpers / short / cancel-and-replace / `get_option_greeks` (SDK-derived, not MCP-verified); exact MCP return-payload shape; `validate_order` exposure; `TWENTY_FOUR_HOURS` acceptance.
