## Headline findings

1. **The chat turn's tool set is the MCP command set, not the MAS tools.** `createMAS` has exactly one production caller — the SearchHub route (`src/agents/routes/searchHub.ts:110`) — so `draftPayment`/`confirmDraft`/`searchKnowledge` (MAS) are route-surface tools, not chat-turn tools. The turn executes through `createAgentMcpTools` (`src/agents/mcpAdapter.ts:76`) via `createTurnTools` (`src/agents/orchestrator/chatTurnHelpers.ts`). (§1, §6.7)
2. **No agent uses the SDK state API.** `grep -rn "setState" src/agents/ src/actors/` returns zero hits. All state is `ctx.storage` KV/SQLite, in several agents behind the actor port's state facet, which is itself a `ctx.storage` passthrough (`src/actors/thinkAdapter.ts:7-9`, `:319-322`).
3. **`durableFibers` is not durable and not the Think/SDK fiber primitive.** It is a home-grown service whose live records sit in an in-memory `Map`; checkpoints are written to an events table but never read back, and the `onFiberRecovered` hook its header advertises does not exist (the only occurrence of the string in `src/` is the header comment itself). (§2h, §6.1)
4. **The DID "attestation" is an unkeyed hash, not a signature.** `createDidAttestation`'s signature is a bare SHA-256 of the payload (`src/agents/did.ts:236`); the sync variant's is a 32-bit string hash (`did.ts:289`). There is no key material and no verify function anywhere in `did.ts`. G14's "existing attestation pattern" is a labelling pattern (proposer/authorizer/executor DID triple), not a proof. (§2-identity, §6.2)
5. **PaymentWorkflow's own header is stale**: it claims "No route calls this workflow yet by default" (`src/workflows/paymentWorkflow.ts:28-34`), but four route/service call sites start it today (behind the default-OFF monetization flag). It also never consults PaymentsAgent (zero `PAYMENTS_AGENT` references in the workflow or its flow) — G5's budget-check-first is new wiring, not an extension of an existing call. (§3, §6.3)
6. **The QA self-healing loop is half external, half dormant.** The in-worker filing function `handleQAFailure` (`src/qa/self-healing.ts:56`) has **no caller anywhere** in `src/`, `scripts/`, or `tests/`; production issue filing is done by the external `scripts/qa-smoke.mjs` (GitHub API at `:169`), and the worker's live half is the investigation route `POST /api/qa/investigate` (`src/server.ts:869`). (§9)
7. **The G0 rename has a migration collision the issue does not mention**: `OrchestratorAgent` is already a registered DO class (migration v9, `wrangler.jsonc`) with its own namespace. A `renamed_classes` migration `SearchAgent → OrchestratorAgent` targets an already-existing class name. (§5)
8. **Synthetic identities are a family, not two cases**: beyond `runDiscovery`'s `"default"` and SlackAgent's `"slack_agent_master"`, the survey finds the orchestrator's own research-stub `"default"` (`orchestrator.ts:593`), seven more `"default"` propagations inside ResearchAgent, PaymentsAgent's caller-attribution default `agentId ?? ## §2 Per-agent conformance matrix

Fleet facts applying to every PortThink agent (evidence once, cited per agent as "fleet"):

- **Base**: every agent class extends `PortThink` (`src/actors/thinkAdapter.ts:121`), which extends `Think` from `@cloudflare/think`, which extends the Agents SDK `Agent`. PortThink defines exactly three lifecycle overrides — `beforeTurn`, `onChatResponse`, `onChatError` (`thinkAdapter.ts:150-197`) — translating to the class's `portHooks` object. It defines **no** `onConnect`/`onMessage`/`onStart`; WebSocket handling is the SDK base's, reached via `routeAgentRequest` (`server.ts:465`, session-gated `:466-481`). A repo-wide grep finds **zero `onConnect` occurrences in `src/`**.
- **State facet**: the port's state/schedule/session facets for Think agents are the cf adapter's, reused verbatim (`thinkAdapter.ts:319-322`): state = `ctx.storage` passthrough, schedule = SDK scheduler delegation (`src/actors/cfAgentsAdapter.ts:47-56`), session = flat `ActorSessionStore` over `ctx.storage` (one key per message + id index, `src/actors/actorSessionStore.ts:41-46`). **The SDK state API (`setState`/`this.state`) is used by no agent** — `grep -rn "setState" src/agents/ src/actors/` is empty; the only `this.state` hits in `src/` are an in-memory circuit breaker and a think-harness provider, neither an agent.
- **Dual session stores** (orchestrator/research/trading, the turn-capable agents): Think's own tree session (branching/compaction/FTS) and the port's flat transcript are separate stores in the same DO; a turn writes to both (`thinkAdapter.ts:72-79`). Tree operations have no port equivalent.
- **Lifecycle precondition**: native RPC bypasses the lifecycle startup that fetch/alarm/WebSocket entry points run; the Think turn path boots it explicitly (`lifecycle.start()`, `thinkAdapter.ts:204-230`). Only OrchestratorAgent defines `onStart` (`grep -rn "async onStart" src/agents/` → one hit, `orchestrator.ts:667`).
- **Fibers (fleet)**: no agent imports or uses any Think/SDK fiber primitive. The only fiber surface in the repo is the home-grown `ETradeDurableFiberService` (§2h detail under OrchestratorAgent, its sole consumer's home).

### 2-identity(c) — the mesh credential, fleet-wide

- **Inbound A2A**: ONE shared bearer token. The dispatcher checks `env.A2A_API_TOKEN` before any resolution — unset → 503, missing/wrong → 401, timing-safe compare (`src/a2a/index.ts:32-53`). The token carries no caller identity: any holder is indistinguishable from any other, and the callee learns nothing about which agent (or human) is calling. This is the gap G14 names.
- **Internal DO RPC**: stub calls carry **no credential at all** — authority is capability-based (holding the namespace binding) **[platform docs: DO RPC within a worker is not authenticated per-call]**. Callers pass identity as ordinary arguments (`userLogin`, `agentId`), which callees trust as asserted — see ReportAssetAgent (2.7) and PaymentsAgent's `agentId ?? "orchestrator"` default (2.4).
- **Per-surface credentials exist elsewhere** (precedents G14 can unify rather than invent): the dedicated `QA_INVESTIGATE_TOKEN` for `/api/qa/investigate`, explicitly NOT the A2A token "different trust domains" (`server.ts:855-869`); per-gateway HMAC signing secrets on the payment-webhook channel (§7); Slack's signing secret (`gateSlackRequest`); the outbound cfpay A2A token (`CFPAY_A2A_TOKEN`, used by `src/services/cfpayA2A.ts`); app sessions for every user-facing door.
- **Attestation verification**: `did.ts` contains **no verify function** — attestations are produced (mas.ts, commands.ts, facade.ts) and stored on draft rows, but nothing in the tree verifies one. Combined with the unkeyed hash (§2.1(h) headline 4), today's attestation is an attribution label, not a checkable proof.
