## 1. Server-side stock strategies / patterns / signals

- **Live path — `src/services/patternSignals.ts` (156 lines).** `SANDBOX_STRATEGY_IDS` (:44-49): exactly 4 ids. `sma_crossover` (:76-99) is the only distinct rule: fast SMA > slow SMA (defaults 5/20, means of closes *before* bar i) while flat → enter long; fast < slow while holding → exit. `rsi_reversal`, `mean_reversion`, `breakout` (:101-117, `meanReversionFamilyAt`) are one shared rule: close >1.5% below prior bar (from bar 14) while flat → enter long; close >3% above entry while holding → exit. **No RSI is computed anywhere** — disclosed in the file header. Consumed by the Stock Copilot cycle (`src/services/stockCopilot.ts:907-917`, `:400-405`, `:343-350`) and by `SandboxService.runQuantBacktest`.
- **Code-gen taxonomy — `src/services/stockCopilotStrategySandbox.ts`.** `StrategyAlgorithmType` (:23-29): 6 members (`momentum_breakout`, `mean_reversion`, `rsi_reversal`, `sma_crossover`, `volatility_breakout`, `custom`). `generateStrategyCode` (:87-272) emits SMA-crossover code for every type; only the summary text differs (`momentum_breakout` claims volume 1.5× + MACD, `mean_reversion` claims Bollinger 2SD + RSI < 30 — none of it in the emitted code). `runStrategyInSandbox` (:273-393) collapses 6 types → 4 sandbox ids and falls back to hardcoded defaults when the backtest returns null (:~360): Sharpe 1.42, max drawdown 3.8%, win rate 62.5%, total return 8.4%, 12 trades. **Never invoked**: no route, MCP tool, schedule, or copilot-loop caller. The hardcoded fallbacks must NOT migrate.
- **Real technicals, unwired — `src/trading/technicals.ts`.** `computeTechnicals` (:943-990): RSI₁₄ (`computeRsi14`, from `src/services/marketDataResearch.ts:17`), MACD (12,26,9), ATR(14), overnight gap %. Also SMA (:92), Bollinger Bands (:133) + Squeeze Gate (:177), Anchored VWAP (:235), Historical Volatility (:331), Fractal Pivots (:382), Fibonacci Retracements (:450), Price Regime (:501), Death Cross (:552), Opening Range / ORB (:709-739, :832), VWAP Hold (:776), Gap classification (:925). None wired into `patternSignals`.
- **Screener classification — `src/trading/screener.ts`.** Signal labels (:826-831, :910-912): `rsi14 > 70` → `OVERBOUGHT`; `< 35` → `OVERSOLD_BOUNCE`; `changePercent > 0.5` → `BULLISH_MOMENTUM`; else `RANGE_BOUND`. `rsi14` here is NOT computed: `calculateDynamicRsi` (:54-64) returns the feed-supplied `q.rsi` if finite, else `undefined`. `momentumScore` (:912): `round(50 + changePercent * 5)`. Standout filter (`src/trading/screenerPipeline.ts:2636-2651`).
- **Screening indicators — `src/trading/screeningIndicators.ts`.** `computeScreeningIndicators` (:135-186): `screenScore` 0–100 heuristic. `compute6VoteCompositeBias` (:261-323): votes `smaCross` (SMA50 vs SMA200), `macd`, `rsi` (RSI₁₄ > 50), `regime` — takes real bar-computed inputs. `dayAction` and `sentiment` are the same value (`sentiment` is the deprecated alias, :175-177).
- **Factor grades — `src/trading/factorGrades.ts`.** Value and Momentum only (:154-214), percentile-based vs universe. `rawMomentumSignal` (:130-136): a third distinct "momentum" computation.
- **Base breakout — `src/trading/baseBreakout.ts`.** `detectBase` (:103-200), 20-bar window (`DEFAULT_BASE_DEFINITION`, :62-66: bars 20, range ≤ 4% of close, confirmation volume ≥ 1× window average); `planBaseBreakout` (:310+) ladder of limit rungs. Unrelated to the sandbox `breakout` id.
- **Governance — weights/policy/bank.** `src/services/strategyWeightsV2.ts`: live screen ranking does NOT read v2 weights at decision time (header :42-48, :71-88). `src/services/strategyPolicyState.ts`: deprecated shim, superseded by `src/data/strategyPolicyPorts.ts` + `doSqliteStrategyPolicyAdapter.ts`. `src/services/strategyBankReselection.ts`: nightly re-run, ranks by `winRate × avgRMultiple` (:194-199), writes proposals only (`mas_strategy_bank_proposals`, :335-338). `src/services/stockCopilotConfiguration.ts`: `mas_settings` key `stock_copilot:strategies` (:21), env `STOCK_COPILOT_STRATEGIES` (:397); `DEFAULT_COPILOT_STRATEGIES` (:31-34) = `[sma_crossover, mean_reversion]`; `parseStrategiesInput` (:173-212) accepts only the 4 sandbox ids and silently drops unknown ids.
- **No unified stock strategy registry exists.** Five vocabularies (live 4 ids, code-gen 6, screener labels, real technicals, weights/policy/bank keys) with overlapping names and no mapping table.

## 6. D1 / DO storage

- **D1 exists:** `wrangler.jsonc` binds `AGENT_DB` (`agentdb`, id `8d1bebf1-b2c4-4a55-8673-03140afb8023`); `src/data/drizzleSchema.ts` defines ~130 tables, all `agent_*`; **no strategy table in D1**. Binding comment (#1546): "shared cross-agent query projection; DO storage stays authoritative for execution state."
- **No strategy-definition table anywhere.** Weights/policy/profiles/reviews live in DO SQLite, per-login-instance scoped, keyed by free-form strings: `mas_strategy_weights_v2` + `mas_strategy_weight_versions`, `mas_strategy_weight_caps` + `mas_strategy_gates`, `mas_strategy_profiles` (named request-field overrides, `profile_<base36>_<rand>`), `mas_strategy_reviews`, `mas_strategy_bank_proposals`, `mas_strategy_bank_active`, `mas_screening_activity`, `screen_run_locks`.
- **DO estate:** 47 `doSqlite*Adapter.ts` files, 50+ classes, 69 CREATE TABLEs in the catalogue — undercounts: ~90 tables per ADR 0022 survey, 186 in `table-domains.md`, ≥14 tables created inline by `src/orm/` (`mas_memory`, `mas_messages`, `mas_transactions`, `mas_trades`, `mas_options_chain_cache`, `mas_stage_claims`, `mas_delivery_claims`, `mas_ladder_states`, `mas_learnings`, `mas_events`, `mas_feed_datasets`, `mas_cancel_previews`, `quote_source_setting`, `breaker_trip_alerts`).
- **ADR 0022 D-G (ratified 2026-10-29):** "No execution state moves to D1 under this ADR." ADR 0033: making D1 authoritative for execution state rejected. Promotion unit: DO `transactionSync` wrap; weights port header states a D1 move "would dissolve the unit." D1 `batch()` atomic per batch; no cross-store atomicity (`TX_CANNOT_HONOUR`). Agent runtime is definitionally a DO. `mas_settings` independently blocked (D-A.5 single-owner ruling G-7). SessionStore migrates last (D-I step 5).
- **Cutover precedent:** IV history #2337 — D1 adapter production when bound, env rollback lever, started empty with no backfill. D1-native substrate families (trace, proposal ledger, fleet registry) are D1-authoritative by D-G.
- **Usage by id today:** track record (`src/services/researchTrackRecord.ts`, #340) reports per-strategy outcomes keyed by the 10-name OODA vocabulary; outcome tracking (`mas_outcome_tracking`) has no strategy-id field (identity only via `screenRunRef` → run → idea `structure`); no usage-count table; no FK from any run to a canonical id. `src/outcomes/outcomeCatalog.json` does not exist.
