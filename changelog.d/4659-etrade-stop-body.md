### Fixed

- **E*TRADE STOP and STOP_LIMIT orders state their trigger (Qunsultant/cfagent#4659):** the place body carried `priceType` and, for limit types, `limitPrice` — but **no `stopPrice`**, so a stop order was correct only if the preview session it referenced still held the trigger, an invisible dependency with no test behind it. `client.placeOrder` now takes `stopPrice` and sends it on the order for STOP/STOP_LIMIT (both the REST place body and the remote `place_order` tool arguments); `PreviewIds` still rides along for the priced preview. A stop order with **neither** a trigger nor a preview id is refused before any broker contact, and that preview-session arm is now pinned by a test instead of assumed. The HITL path (`platform.executeOrder`) forwards the draft's stored `stop_price` (#4654), so an approved stop order is placed with the price the user saw.
