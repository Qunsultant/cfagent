### Fixed

- **Every HTTP 401 in the server routes now answers JSON with a code (#5699):** the repo had two idioms for the same refusal — `Response.json({ error: "Unauthorized: Please log in." }, { status: 401 })` in some branches and `new Response("Unauthorized", { status: 401 })` in 23 others (trading ×10, auth ×7, platform ×3, messaging ×2, product catalog ×1). The bare-text shape is what reached a user as `Unexpected token 'U'` in #5625. One helper, `unauthorizedJson()` (`src/server/routes/apiRefusals.ts`), returns `{ code: "UNAUTHORIZED", error }` with `application/json`; the forwarder fixed in #5625 and every listed site use it, and the one site with a specific message (`Unauthorized: sign in to approve a trade.`) keeps its text. The WebSocket upgrade refusal stays plain text by design — the handshake body is not parsed — and is the single allowlisted site in a new census pin (`tests/unauthorized_json_5699.test.ts`) that fails if a bare-text 401 reappears. The existing guard census (`fallback_identity_session_gate.test.ts`) now counts the guard in either form, so its meaning survives the body change. #clo-arsi
