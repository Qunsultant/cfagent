### Added

- **Cancel is now a per-stage action in Workflow Runs (#5837):** a stage already offered re-run, stop and resume; the engine's `cancelStage` existed with no button, so an operator could stop a stage and resume it but never *cancel* one from the run's detail view. The stage row now carries a **Cancel** action beside the other three, using the same `controlJobStage` seam and the same operator gate — so the button's promise is the engine's own operation, not a second path. The route already accepted the `cancel` operation (`JobStatusOperation` includes it) and the client seam already typed it; only the panel was missing. Pinned by `tests/stage_cancel_ux_5837.test.ts`, which also drives `POST /api/jobs/:id/stages/:stage/cancel` through the route to prove the operation reaches the engine. #ceo-aimp
