### Changed

- **Scheduling consolidation, Phase 2 #3123 — one schedule store, one run ledger, one management path (Qunsultant/cfagent#3123):** six schedule stores become one logical store (`unified_schedules`, one `ScheduleStore` port, DO SQLite adapter + in-memory double); pause is a record state, so resume re-arms the SAME record id (no copy-and-recreate identity churn); the goals KV key migrates into the store with a one-way import; the split run ledger becomes one physical ledger (`recordLedgerRun` is the single DO-SQLite write entry, `GET /api/ledger/runs` is the one merged read) with existing KV rows still readable through it; management converges onto one service (`unifiedScheduleManagement.ts`) and one client module (`jobsApi.ts`, `listAllRuns`); worker duties become records (`workerDutiesFromInventory`); maintenance wipe still clears paused records only. Five duplicated modules retire by deprecation rename only (zero deletions). No capability, timing, firing-time, cron-expression, or payload change; worker crons stay OFF. ADR 0029.
