### Fixed

- **Resume and replay now execute the definition version the run started under (#5278):** `resumeJob`, the running-instance `replayJob`, and `resumeStage`'s follow-on resume all said "the current definition" and re-read today's pointer, so a reconfigure mid-flight silently changed the semantics of a run that was already half-executed — the execution half of #5887's stamp. Both paths now resolve `instance.runDefinitionVersion` through the append-only version store and execute exactly that version; a run whose version was never retained (`resume_pre_retention_run`) or is no longer resolvable (`resume_definition_version_unresolved`) refuses by name and names the recovery (a retry starts a new run on the current definition). A stage retirement stays today's operator veto (#3944) — a retired stage never re-runs, whatever version the run started on — while the execution it resumes pins. New runs are unaffected: a reconfigure applies to the next dispatch. Pins: `tests/job_definition_version_resume_5278.test.ts` (five cases: the pin, both refusals, the running-instance replay, and the new-run boundary); the engine reference (`docs/architecture/agentic/j-stack-workflow-engine.md` §3.8, §3.10, §4.1) now states the pin instead of the gap.
