### Changed

- **Workflow Runs is a filtered view of the one run ledger (#4262 S2):** `?tab=workflow-runs` now lands on `?tab=schedules&view=runs&kind=workflow`, so the repo has one run list instead of two. The ledger attaches the workflow-runs read to its own rows by linkage (`asyncJobId`/`workflowId`/`jobId`) — a run the ledger already carries is never listed twice — and a run with no ledger twin appears as one row stamped with the family the store recorded (options/stock/strategy) or `workflow` when it has none. Opening a folded row shows the same detail dialog as before (stages, inputs/outputs, artifacts, delivery states), from the same component — no second detail implementation. A status/trigger the ledger cannot represent is left unrecorded rather than coerced, and a failed workflow-runs read never empties the ledger. #autoclaw-001
