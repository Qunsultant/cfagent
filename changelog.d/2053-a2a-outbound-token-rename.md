### Changed

- **A2A token naming trap resolved (Qunsultant/cfagent#2053, under #1717):** the outbound cfpay A2A Worker secret is renamed to the direction-explicit `CFPAY_OUTBOUND_TOKEN`, read first by `getCfpayConfig` in `src/services/cfpayA2A.ts`; `DASHBOARD_API_KEY_IS_A2A_TOKEN` is kept only as a deprecated transitional fallback (superseded by `CFPAY_OUTBOUND_TOKEN`) and `CFPAY_A2A_TOKEN` as the pre-existing third fallback, and deploy.yml now writes the new name alongside the old one from the same GitHub-secret source, so live outbound dispatch cannot break across the deploy boundary. Inbound dispatch is untouched: `A2A_API_TOKEN` is never aliased to an outbound name, still fails closed (503) when unset and 401 on a wrong token, and is never written by deploy. Both directions, their names, and their enablement states are documented in one place, `docs/architecture/security/api-security.md` §6. The old outbound name is retired only by a later owner-directed removal once the new secret is proven live. #CISO-bhdm
