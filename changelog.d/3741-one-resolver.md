### Added
- The one per-agent config resolver (#3741): every capability enable and every documented choice now resolves through one service (src/services/agentConfigResolver.ts) keyed by agent identity (class and/or copilot registration/surface) + entry id, returning the value with its effective source NAMED (pin / run / session / user / stored / env / default). The existing family resolvers delegate to it with their public shapes, keys, and behavior preserved: the copilot channel switches and the per-surface voice backend keep their stored > env > code layering per registration/surface; the chat/NLQ choice composes its run > session > user carriers with a new per-class/per-registration stored layer above the CHAT_NLQ_MODE env default (production behavior identical: chat default, NLQ selectable); the screener ND gate gains a stored layer for hosts that supply a settings reader, its env-only seams unchanged. Operator pins (AGENT_CONFIG_PINS, set empty in production) freeze an entry at the operator layer and are named as the source; stored-layer writes run through a new door in the copilot-channels route family (GET/POST /api/copilot-channels/config) over the platform's existing settings machinery — audited (agent_config.write / agent_config.write_refused), last-writer-wins per layer, pin refusals enforced by name (AGENT_CONFIG_PINNED) — which also gives the #3796 voice-backend surface keys their first write path. The capability manifest now carries requires metadata: with state disabled by config, the manifest and the resolver name every enabled capability that requires state (capability_requires_state:<id>) instead of letting it serve silently.
