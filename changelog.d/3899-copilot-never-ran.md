### Fixed

- **Stock Copilot never executed a cycle (#3899):** the cycle's only trigger, the Think task `stock-copilot-paper-cycle`, was declared from `getScheduledTasks()` data that cannot exist at cold start (the screener execution context is written only by the first authenticated request), and nothing ever re-evaluated the declaration. `OrchestratorAgent.onRequest` now calls the SDK's prescribed `internal_reconcileScheduledTasks()` hook exactly when the stored context changes, and `onStart` reconciles after maintenance — both best-effort, so a reconcile failure never fails a request or blocks startup. Agentic-mode refusals (`disabled`, `mode_unresolved`, `inactive_broker`, `outside_enabled_sessions`) now append an activity record, mirroring the deterministic path (outside-sessions keeps the one-transition-record dedup), so `lastCycle` reflects every firing. The status surface (door + REST) reads the real stored broker selection through the commercial store — no hardcoded Alpaca default — and reports `never_executed` instead of `live` when no cycle has ever run (no activity record and no cycle row in the runs ledger). When the universe preset is NASDAQ100 the cycle resolves the stored 100-member list via `resolveStoredIndexList`, with the 12-symbol preset as the labelled fallback (reason audited per firing) when the list is missing, stale, empty, or unreadable. A parallel ScheduledAgent goal as a second trigger was considered and rejected: it would double-fire cycles with no dedup. #CISO-bhdm
