### Added

- **Regenerate an options run from its stored record (#2603, #2528 slice 6):** `POST /api/trading/options/regenerate` re-runs the SAME request rebuilt server-side from the stored canonical row (`{ reportId }` or the owner's latest options run) and executes it through the existing unified options path — so the new run is recorded under its own generation id and the original row is never written. `rebuildOptionsRegenerateRequest` is pure and REFUSES with the missing field names (422) when the stored record cannot name the request (no symbol, unreadable body), instead of guessing; the rebuilt request carries `regeneratedFrom` / `regeneratedAt` / `regeneratedBy` provenance. The run detail gains a "Regenerate this run" action (`RunDetailView`, `regenerateRunId`), which posts the stored run id and reports the server's refusal verbatim. The thin-router inventory caught the first placement of the route nested inside the unified guard — it is a sibling endpoint now, pinned in order. 9 new pins; 76 targeted tests green across the options-route, run-detail and router-inventory suites.
