### Added

- **Upgrade offers, slice 1 — server derivation, routes, rules, dismissal, rank (#3246, sub-issue of #3241):** an offer is a server-computed, read-only presentation of server truth — the caller's current position (account, held version, coverage) against the higher approved effective versions for their segment — computed deterministically on every request and never stored. New pure `resolveOffer()` service (`src/services/upgradeOffers.ts`) over the existing ports: the §2.3 eligibility rules in order (Flagship flag, operator offer rules, per-(login, trigger) dismissal, the gate's coverage order read-only with no consumption, purchasable-action fallback, the quota at-limit action), the §3.3 ladder (explicit operator rank first, then the derived order; recommended = the nearest step up), approved-higher targets, ambient-only downgrade targets (buy action disabled on Billing-managed held rows), PROPOSED versions as unavailable targets, the monthly/annual option with integer-cent savings, and referral/free-access mentions. Four routes in the existing commercial route file: `POST /payments/agentic/commercial/offer` (triggered offers; audits `commercial.offer.shown` on every eligible response), `GET /payments/agentic/commercial/offer/compare` (pure read; populates `downgradeTargets`, ignores suppressions), `POST /payments/agentic/commercial/offer/dismiss` (audits `commercial.offer.dismissed` before writing), and operator-only `POST /payments/agentic/commercial/products/:productId/rank` (409 for `prod-free`). Offer behavior rules are one new billing-policy key (`offer_rules`: master switch, five trigger toggles, 1–365-day dismissal cooldown seeded at 7, proposed/downgrade/pack visibility, mention toggles) through the existing operator-only billing-policy route. Dismissal is a per-(login, trigger) server-side suppression (`agent_offer_suppressions`, migration 0062, which also adds the nullable `agent_products.rank` column and backfills `prod-free` to rank 1). The existing subscription-checkout and top-up mints accept an additive audit-only `offerContext` (ignored when absent, audited as `commercial.offer.accepted` when present); no purchase path changes. No UI (slice 2), no gate changes and no runs-pack tables (slice 3), no price approval, no flag/grant/secret changes. Pins in `tests/upgradeOffers.test.ts`, `tests/upgradeOfferRoutes.test.ts`, `tests/offerSuppressions.test.ts`, plus the offer-rules block in `tests/monthly_annual_plans_3357.test.ts`, the rank block in `tests/productVersions.test.ts`, and the thin-router inventory pin (456 entries).
