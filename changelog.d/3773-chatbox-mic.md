### Chat box voice channel with dual speech backends (#3773)

- The copilot chat composer gains a voice channel: when the active copilot registration's voice channel resolves effective, a mic control renders above the composer — a captured transcript submits as a normal user turn through the same send path as typed messages, and the assistant's reply to a voice-submitted turn is spoken back (with a mute toggle); typed turns are never spoken.
- New read `GET /api/copilot-channels?registration=<id>` projects any registration's channel switches through the same server-side projection the Stock Copilot status read serves (#3738 switch resolver composed with the #3720 activation), so the gate is data-driven for every registration — no "stock only" special case, no client-side precedence.
- The voice channel runs on one provider seam with two backends, chosen per registration by an externalized switch (`COPILOT_VOICE_BACKEND` / stored setting, stored > env > code default): `webspeech` (browser Web Speech, the default) or `model` — MediaRecorder audio transcribed by a Workers AI STT model and replies synthesized by a TTS model through new session-gated endpoints (`POST /api/copilot-channels/voice/stt` and `/voice/tts`), with the model ids resolved through the platform model resolver (task keys `voiceStt` / `voiceTts`). Backend failures surface by name (`voice_stt_model_failed`, `voice_tts_model_failed`, `voice_backend_unavailable`) and never fall back silently to the other backend.
