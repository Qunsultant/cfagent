### Changed

- **Shard children signal completion; the parent waits instead of polling (#3025, follower of #2601):** `ScreenerScreenWorkflow`'s shard run sends `SHARD_DONE_EVENT` to the parent instance id carried on the command (`parentWorkflowId`), swallowed on failure so a lost signal costs a wait, not a run; `runParentFlow` waits with the step surface's `waitForEvent` bounded by the nearest shard deadline and reconciles with a **single** `getChildStatus` sweep per wake — the per-round sleep/poll loop is gone from the production path. A step surface without `waitForEvent` (test doubles, older adapters) keeps the deadline-bounded sleep, so the decisions are identical either way, and a child started by an older parent simply never signals — the deadline sweep covers it. Timeout still resolves as `timed_out` with a qualified partial. Pinned by `tests/wait_event_3025.test.ts` (7) plus the workflow, driver-wiring and seam C suites (55 in the targeted run).
