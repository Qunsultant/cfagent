### Added

- **One parameterized technicals job persists daily-bar history, and every enrich job joins it (#3931, sub-issue of #3929):** the Yahoo technicals job (`yahoo-nasdaq100-technicals`) persists 60 daily bars per symbol (one job definition, parameterized by universe — its universe is a run input naming the stored index list; default nasdaq100, kept for lineage) instead of a second job definition per universe, per the owner's Correction 2 on #3931 (issue comments 6760485030, 6760545755). A provider without the `historicalBars` capability refuses with `FEED_PROVIDER_HISTORICAL_BARS_UNSUPPORTED`, and a symbol with no live bars is skipped, never zero-filled. Every quotes enrich job (Yahoo, Alpaca, E*TRADE, Public — every universe) now joins the parameterized technicals dataset for its own universe and carries `rsi` / `macd` (`macdLine`, `macdSignalLine`, `macdHistogram`, `macdSignal`) / `atr` computed from the persisted bars with the same functions as the live leg (`computeTechnicals` / `computeAtr`, guarded by minimum bars — RSI(14), MACD(12,26,9), ATR(14)); a missing technicals copy is a named `requires_daily_bar_history` gap and a partial run, never a fabricated value, and a missing symbol or too-short history is a named per-symbol gap. Per-join-source missingness is tracked separately, so a missing technicals copy no longer mislabels fundamentals gaps as `join_dataset_missing`. Each chain folds the technicals node in with the chain's universe as its input (feed → fundamentals → technicals → enrich → analyze → generate → deliver). Per-job opt-out stays behind `ENRICH_JOB_<JOB_ID>_TECHNICALS_JOIN` (`auto`/`on`/`off`, default `auto`). The screener UX now reads persisted technicals as its primary source (fresh copy first, live Yahoo fetch kept as the fallback when persisted data is absent or stale) and gains an ATR(14) column. #CISO-bhdm
