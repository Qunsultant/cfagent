### Added
- Feed jobs S2 (#3530): the E*TRADE and Alpaca sources join the feed-job registry on the same S1 contract — `etrade-nasdaq100-quotes` and `alpaca-nasdaq100-quotes` (quotes for the stored Nasdaq-100 universe, persisted as the local copy in the feed-dataset store, reads served from the copy with age + provenance; the data-providers routes wire both sources' capture-wired adapters by default). Alpaca's wrapped provider gains the batch leg the adapter factory requires (`AlpacaMarketDataProvider.getQuotes` over the multi-symbol snapshots endpoint — one request per batch, #923 fail-explicit honesty), so its captures land in screening's market-data shape. Credential honesty is pinned end-to-end: an E*TRADE run with no live token for the session login ends in a recorded FEED_NO_QUOTES_RETURNED / FEED_FETCH_FAILED failure, and an Alpaca run with no configured key/secret ends in FEED_FETCH_FAILED carrying the no-substitute message — never fabricated rows, never an empty success. Nasdaq deliberately gets NO feed job in this slice: its adapter declares only `screenUniverse` and its dataset (the US listed-securities universe, `NasdaqStockListing[]`) cannot be expressed by the quotes-shaped feed contract without fabricating quote rows or inventing an index id — the misfit is recorded on #3530 and the surface keeps answering an honest null feed block + typed 404 for Nasdaq until a universe-dataset contract extension is decided.
