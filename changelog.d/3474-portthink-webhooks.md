### Added

- **Webhooks by default on PortThink (#3474, owner directive 2026-11-06):** every agent behind the Think port (#1951) now has the Agents SDK's built-in webhook channel exposed and routed, with no per-agent wiring. `PortThink.fetch` intercepts the reserved `/webhooks/<source>` path tail — at fetch, not `onRequest`, because four fleet classes (Orchestrator, Browser, Slack, Sandbox) override `onRequest` as their whole HTTP router and never delegate to super, while every production dispatch (`actorGateway.dispatch`, `routeAgentRequest`) terminates at the instance's `fetch` — verifies the delivery, and dispatches it to the port hooks object's new `onWebhook` hook with the verified payload, raw body, source, and headers. Verification is the docs pattern (HMAC-SHA256 over the raw body, `X-Hub-Signature-256`, `crypto.subtle`) against the deployment secret in env `THINK_WEBHOOK_SECRET`, and the pipeline fails closed in order: non-POST ⇒ 405; no secret configured ⇒ 503 (enabled in code, closed until the credential exists); bad/missing signature ⇒ 401 with the body never parsed first; unparseable body ⇒ 400; no `onWebhook` hook ⇒ 405, so an agent that has not opted in cannot be driven by a webhook. A hook ending in `setState(...)` uses the base Agent's own broadcast to connected websocket clients, unwrapped — the mechanism the selection-change notification (#3471) and the websocket leg (#3472) build on. ThinkWorkflow is untouched (no workflow port exists). #CAIO-quns
