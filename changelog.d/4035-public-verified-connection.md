### Added

- **A Public.com connection now carries its verification evidence (#4035):** the Settings card could only say "Connected" or "Not connected" — a boolean over a per-user credential that was verified against Public's MCP server (`tools/list`) before storage. The token set now records `verifiedAt` and the tool names the verification observed, the neutral status read (`GET /api/broker/connect/public`) returns them, and the card renders `Connected (personal, abcd…wxyz) · verified <time> · <n> tools`. A connection that verified but observed **zero** tools shows a warning instead of a green line, so a token without the data scopes is visible rather than silently useless. Pinned in `tests/step5c_token_ports_conformance_2434.test.ts` (connect → evidence → status) and `tests/public_broker_3990.test.ts` (the status payload and card carry the fields).

- **Credential note:** Public.com needs **no** Worker secret and no `wrangler.jsonc` entry — the credential is the signed-in user's personal access token. The `PUBLIC_API_KEY` / `PUBLIC_LIVE_URL` GitHub secrets are read by nothing and are not synced by `deploy.yml`; #4035 tracks the decision to wire or delete them.
