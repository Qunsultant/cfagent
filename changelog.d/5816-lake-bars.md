### Added

- **Technicals bars are now archived as lake events, with a runbook that makes the lake operable (#5816):** `ANALYTICS_LAKE_GRANULARITY=bars` switches the archiving aspect from one event per artifact to **one event per (run, symbol)**, carrying that symbol's compacted bar series (`[date, open, high, low, close, volume]`) plus run provenance — so Basin/Iceberg holds market history, not just run history. `ANALYTICS_LAKE_MAX_EVENTS` (default 500) caps a run's events and logs `analytics_lake_max_events` with the dropped count instead of truncating silently; symbols with no usable bars are skipped rather than emitted empty. The wire body now carries `payload` as a **JSON string**, which is what a scalar-typed Basin stream schema accepts — the mismatch that would have rejected every event. `docs/operations/analytics-lake-basin.md` documents provisioning (bucket, catalog, compaction, stream schema, sink, pipeline SQL), the Worker settings, how to fire a run, the three verification checks, the query commands for both granularities, a troubleshooting table, cost/volume per run, and how to switch it off. Default deployment behaviour is unchanged: `off`, `dataset` granularity. #ceo-aimp
