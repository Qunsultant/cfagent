### Added

- **A running job can be queried for its live state (#5279, query half):** `getJob` answers from stored views, so a run in flight looks like whatever was last written. `queryJob(jobId)` answers what only the executing process can prove — whether it is executing one of the run's units right now, which `stage:unit` are active, and how many steps have started — and reads `live: false` for a run executing elsewhere, which is the honest answer rather than a guess at another isolate. Read-only by contract: nothing is written and no state advances. The signal half is NOT built here: delivery to a parked `wait.event` already exists via `sendEvent`, while a recorded, boundary-honoured signal needs semantics the owner must name — recorded as a decision on the issue. Pins: `tests/job_query_live_5279.test.ts`; the engine reference (§3.9) states the query.
