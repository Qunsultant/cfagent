### Added

- **Report replay from persisted data (#2863, under #2764):** POST `/api/reports/replay` (`{reportId | runId | symbol}`) returning the persisted report with replay provenance (`kind: "replay"`, `charged: false`, `liveFetch: false`) — zero live re-fetch (the replay builder takes the persisted record as its only input and imports nothing callable live), no re-charge (no payment path touched, no job/workflow started, no new canonical row written), partial marking when persisted data is incomplete (missing criteria/standouts/artifacts), loud failure when the row is missing/unowned (404), the body unavailable (500), or the body unreplayable (422 — never regenerated). New `src/workflows/reportReplay.ts`, owner-scoped `getScheduledReportByRunId` (stored `screener:<timestamp>` generation lookup), REST runs now record their criteria in the canonical body (additive `criteria`/`patternRef`/`presetRef` fields; older runs replay with a partial criteria gap). Replay buttons only on the three named surfaces: ReportsPanel per-row, RunDetailView ("Replay this report", wired from the ScreenersHub auto-runs feed via `screener:<timestamp>`), and the Research Report subtab (newest stored research report for the active symbol, verbatim). No button in New Screen. No second recorder/catalog/port layer; the endpoint reuses the canonical report store, `resolveCanonicalReportBody`, and the audit path.
