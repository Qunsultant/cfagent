### Added

- **Order modification is real on Alpaca: `PATCH /v2/orders/{id}`, with the refusals that make it safe (Qunsultant/cfagent#4670):** `validateReplaceOrder` had no caller and there was no PATCH anywhere, so changing an open order meant cancel-and-replace — losing queue position and, for a bracket, detaching the held legs. Now the provider sends a real PATCH carrying **only the fields the caller changed** (quantity, limit, stop, time-in-force, trail), and `replaceOrderRemote` **reads the order first** so the refusal is factual: a compound parent (`bracket`/`oco`/`oto`) answers `replace_parent_unsupported` rather than being replaced and divorced from its legs, and an order that is no longer open (`filled`, `canceled`, `expired`, `rejected`, `replaced`) is refused naming its status. The neutral `POST /broker/order/replace` route and the new `alpaca_replace_order` tool (`mcp:trade`) both call that one method, so the API and the agent cannot disagree, and a broker without the capability answers `provider_unsupported` — never a silent cancel-and-replace. A request with nothing to change is refused before the wire. E*TRADE and Public keep their documented endpoints as follow-ups (change-order; `PUT Replace order`).
