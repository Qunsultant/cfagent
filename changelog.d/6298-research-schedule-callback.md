### Added

- **The OODA run is reachable from a stored schedule — its own callback, through the one run path (#6298, #6029 (a) part 1):** `runResearchSchedule` is now a creatable schedule callback (`POST /api/schedules/create`) beside `runPipelineJobSchedule`. It fires `runResearchAndPublish("scheduled", owner)` — the same path a manual run uses, and the one place the six stage dependencies are wired — instead of routing through `runPipelineJobSchedule`, which lands on the ScheduledAgent door whose research deps are the fail-closed defaults (`FAILURE_RESEARCH_DEPS_MISSING` at analyze) and would therefore produce a hollow run. The payload carries the owner (falling back to the configured service identity like the other scheduled callbacks; an unowned firing is skipped, never run as "default") and the run records through the same `recordScheduleCallbackRun` seam as every other callback. The record's id is the ledger join: created as `nightly-research`, a scheduled run joins the rows an operator already reads. Not account-scoped, for the same reason `runPipelineJobSchedule` is not — the run resolves its venue from the tenant binding at run time (`resolveResearchVenue`, #6036) and refuses an unsupported pair by name. Pins: the allow-list and its inventory mirror, the non-account-scope decision, the ledger join, and the dispatch method. #COO-spr9
