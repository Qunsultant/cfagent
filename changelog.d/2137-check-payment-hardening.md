### Check-payment ownership hardening (#2137)

- The production submission/check-payment route now verifies that the verified session login owns the submission being verified before any Stripe retrieve, audit scan, or facilitator call: a paid-submission record owned by another login is refused with 403 (cross-user and cross-tenant alike, since ownership is per-login and tenants derive from the login, never from a client-supplied tenantId), and an unbound commercial store fails closed with 503. Verification semantics are unchanged: payment_verified is still delivered only when the native rule holds.
- Residual, stated plainly: when no paid-submission record exists (a pre-record legacy run, or the redeemed path's best-effort record failure), there is no owner to check against and the route follows the legacy verify path; a strict unknown-to-404 flip is a follow-up needing the existing check-payment fixtures to seed a paid submission first.
- Native slice-3 (UI rework) leftovers: none found — the CheckoutPanel already covers every #2137 "What this slice builds" item (pay-per-run panel with goal helper, payment_started polling + verify, flag-OFF free path, server-truth pricing + failure policy, testnet disclosure; subscription panel with plans, checkout-to-purchase activation, cancel-at-period-end copy, status display, repurchase-renewal copy; fixed per-status error strings; subscription-404 not-deployed degradation). No UI change in this slice.
