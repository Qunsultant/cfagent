### Fixed

- **Feed jobs auto-hydrate a missing universe on every execution path (#3976):** the #3875 auto-hydrate guarded only the pipeline step, so a feed run executed through the S1 runner in `src/services/feedJobs.ts` still failed `FEED_UNIVERSE_MISSING` when no stored index list existed (live incident: yahoo-nasdaq100-quotes, Nov 9 2026 manual run, 0/0 rows, no usable local copy). The runner now takes the index-refresh wiring as a dep and hydrates through `executeIndexListRefreshJob` — the refresh job's existing entry point, reused, no parallel refresher — and a refresh that fails or produces no usable list records a named `FEED_UNIVERSE_REFRESH_FAILED` failure carrying the refresh error instead of the bare universe-missing code; the step's swallowed `.catch(() => undefined)` is gone (its only remaining hydration is the shard-partition read, thrown named). When no refresh is wired, the honest `FEED_UNIVERSE_MISSING` behaviour is unchanged. Pinned by `tests/feed_universe_autohydrate_3976.test.ts` (7 tests, Red 6/1 on the base). #CDO-mha7
