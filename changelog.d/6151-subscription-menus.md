### Added

- **Subscription-driven menus (Qunsultant/cfagent#6151, S2):** `GET /api/platform/nav-availability` now enforces the product→menu mapping in config (`src/client/nav-config.json` `productMenuMapping`): a nav id named in the mapping stays visible only while the caller holds an active subscription for a product that enables it (tier Subscribed + unexpired row — the same `periodEndMs > nowMs` rule `resolveEffectiveTier` uses, so cancel keeps access to periodEnd and refund revokes immediately). Admin personas bypass the narrowing and see the entire menu; unmapped ids pass through from the persona default, and a product with no mapping entry enables nothing. The mapping ships empty — products are operator data and no subscription-product id is fixed in code — operators add entries as products are created. The preset maps moved into shared data (`src/client/navPresets.ts`, imported by NavigationMenu, Chat, and NavSettingsPage), so the server expands ANY preset key instead of only `alltabs` (sub-item keys follow their parent). New pins: the subscription enable/disable matrix (subscribe / unsubscribe / cancel-keeps-access / refund-revokes / unmapped-product / admin bypass), `expandPresetKey` for every key, the active-row rule, the gating OR, and the mapping normalization.
