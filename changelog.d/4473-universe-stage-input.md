### Universe deps travel as a stage input (#4473)

- A run may now carry a serializable universe descriptor (`classInput.universeDeps`) as a stage input: the start seams validate and stamp it, the resolving steps decode it and rebuild live universe deps per invocation through the residency factory (`resolveUniverseDepsFromStageInput`, over the D1 data-provider ports with no SqlStorage handle), and the shared rebuild constructs every screener with them — so a discovery-mode screen through the host flow resolves its underlyings instead of throwing the #1378 error. Runs carrying no input are untouched: the factory is never called and the screener is constructed as before.
- The goal seam's discovery-mode refusal narrows: a discovery-mode goal leg carrying the universe input dispatches (both the goal run id and the universe descriptor stamped); one carrying neither explicit symbols nor the input still refuses by name. The #4450 manual-route gate stands unchanged — the cutover slices own lifting it.
- `nasdaqUniverseRouteBundle` accepts a ports-only build: the sql handle is optional when both D1 ports are supplied, and the bundle throws by name when either half (config reads, capture/outcome writes) has no store. All existing callers pass sql and are unaffected.
