### Added

- **`wait.sleep` — the durable park (#6393):** #3955 gave the engine a durable *event* wait; a wait expressed as a duration could still only hold, keeping the isolate resident with the run open, and dying with it. `wait.sleep` is the other half of the primitive: a reserved step that parks the run for a declared `params.durationMs` on the host's own timer (`step.sleep`, wired through `sleepChannelFromStep` into `JobPipelineDeps.sleepFor`), resolves to a declared `{ outcome: "slept", durationMs }` that becomes the next step's input, and computes its platform name once (`sleep:<step execution id>`) so a replay re-arms the same park. It follows the event wait's three rules: never inside `step.do` (a journaled sleep would replay as completed), bounded by configuration (`pipeline.sleepMaxDurationMs`, settings beat env, default one day, clamped like the #6551 wait bound), and a host with no durable sleep refuses by name (`stage_port_unavailable`) rather than degrading a park into a hold. A duration past the bound refuses instead of being silently shortened. Pins: `tests/durable_sleep_6393.test.ts`; the engine reference (§3.2) states the step beside `wait.event`.
