### Added

- **Async jobs now execute through the engine's async single-unit capability (#6554):** `JobPipelineControl.runAsyncUnit` runs each executor capability (`http.request`, `mcp.tool`, `task.draft`, `followup.report` / `deliver` / `notify`, `shard.execute`, `feed.snapshot`, `nlq.execute`) as a registered engine step (`async.capability.<capability>`) and records the unit as an engine run (`async.<capability>`, carrying the dispatching async job's id). The executor's capability if/else is retired; the claim, heartbeat, execution deadline, and terminal row stay with the executor, and a context without a wired engine falls back to an in-process control. Unknown capabilities refuse by name (`async_capability_unknown`). The queue row stays the durable truth until the F5 ledger unification (#6101).
