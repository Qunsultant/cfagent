### Added

- **A governed proposal can be filed from the panel (#5527):** #5057 gave the pathway a dispatch through MCP, but the browser cannot call MCP — so the product that produces proposals could not file one. `POST /api/stock-copilot/proposals/file` now exposes that dispatch over HTTP with the same gate: no `approve: true` → `COPILOT_PROPOSAL_APPROVAL_REQUIRED` (400), unknown gap → `COPILOT_PROPOSAL_NOT_FOUND` (404), no token → `COPILOT_PROPOSAL_FILER_UNAVAILABLE` (503). The Stock Copilot panel gains a **Governed proposals** section that loads on request, lists the gaps, and files one after an inline **"File as a GitHub issue?"** confirmation — the approval is the point, not a formality. On success the row shows `Filed #N` and links the issue; a refusal renders the server's own message (the missing-token text). Reuses `fileGovernedProposal` / `resolveCopilotProposalFiler` from #5057 — no second filer. Pinned by `tests/stock_copilot_proposal_route_5527.test.ts` (400/404/503/200 + path isolation) and `tests/stock_copilot_proposal_card_5527.test.tsx` (load-on-request, confirm-before-file, success stamp, refusal text); the route-inventory pin gains the one new path. #clo-arsi
