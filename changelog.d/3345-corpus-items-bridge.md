### Added

- Corpus items-API bridge (issue 3345): corpus documents are now indexed into the Cloudflare AI Search instance through the namespace binding's items API — the same upload executor report indexing uses — under `corpus:<bucketKey>` document ids with provenance metadata (kind, key, SHA-256 of the served bytes, stored-at, title, category, source URL). The bridge fires on corpus writes (the upload route reports the honest indexing state) and as a backfill leg of the corpus sync, which now reports per-item indexing state (indexed / not configured / failed) that the Search Hub Corpus tab renders. It is flag-gated by `AI_SEARCH_CORPUS_INDEXING_ENABLED` (absence = off, deliberately not in wrangler vars): with the flag off, corpus writes and syncs succeed exactly as before and report the indexing state as not configured. Corpus items are platform knowledge — the AiSearchAgent's report login discipline never withholds them — and the shared chunk mapping now resolves a corpus document id back to its servable bucket key, so corpus results render their bucket key and served-file link on every surface.
