### Added

- Automated DO SQLite schema-migration framework (#1767, #1717 slices F-37 / F-38): a versioned, ORM-managed DDL mechanism replacing scattered manual string-query migrations as the way new schema changes land. Port `src/ports/schemaMigration.ts` (migration objects, pure drift computation, fleet rollup shapes), runner `src/data/doSchemaMigrations.ts` (applies declared migrations in order against a DO instance's SQL surface, idempotent re-apply, marker-LAST ledger `mas_schema_migrations` — the ledger row is written only after the migration's statements succeed, so a throwing migration retries cleanly; latest-applied-only rollback via `down` statements, ledger row deleted last; per-instance `checkDoSchemaDrift` comparing the declared set against the ledger, with missing = pending and unexpected = applied-but-undeclared drift, plus a pure cross-instance aggregator), and one scoped switch `SCHEMA_MIGRATION_MODE` (managed|legacy, run > session > user > env > built-in legacy, invalid fails closed to legacy with a schema.config_error signal; no production value set). Proof wiring: the screener's run-lock store is the first framework store — its DDL lives in exactly one place shared by the legacy branch and migration v1 (`0001_screen_run_locks`, IF NOT EXISTS so legacy-created tables converge), `ScreenerAgent` resolves the mode from Worker env, and legacy mode (the default) keeps byte-identical old behavior. Pinned by `tests/schema_migrations_1767.test.ts` (TDD red-first, 15 tests). Honest boundaries, named not hidden: only opted-in stores run through the framework — every other adapter's legacy ensureSchema is untouched, and migrating the remaining stores is follow-up work, one store per slice; the cross-instance rollup needs a consumer collecting per-instance reports (shapes + pure aggregator provided, no collector or endpoint in this slice); the framework does not snapshot/export schema state (that is the #1766 R2 snapshot leg); the D1 `_migrations` runner and the DO generation marker are untouched and keep owning their stores/counters; the switch governs a schema-write mechanism, never an IAAA or HITL gate. No endpoint removed; no code path deleted.
