### Added

- **Options screening is now broker-neutral (#3272 S1):** `DynamicOptionsScreener` was constructed with an `ETradeRestClient`, so the "screening is provider-side" rule (`marketScreening: false` for Alpaca in the catalog) held on paper and failed in code — an Alpaca tenant could not screen options at all. It now depends on `OptionChainSource` (`src/trading/optionChainSource.ts`): anything that can answer "chains for this underlying" and "expiries for this underlying". A platform satisfies it (`platformChainSource` adapts `ITradingPlatform`, returning `null` when the broker has no options data plane), an E*TRADE client still satisfies it structurally, and a test double satisfies it. The screener no longer imports the E*TRADE client at all — a structural test fails if that coupling returns. New neutral route `POST /api/broker/options/screen` screens with the **selected** broker's chains and keeps the `/broker/options/*` honesty rules: a broker the catalog says cannot screen answers `501 provider_unsupported` naming it, and a platform missing the method at runtime does the same — never an empty result. `UnifiedOptionsService.runStrategyPipeline` / `scanOpportunities` accept the port too, so the strategy and opportunity paths no longer require a broker client to be constructed. E*TRADE behaviour is unchanged: every existing call site passes the client, which remains structurally valid, and the 34-file screener/strategy suite is green without edits. #ceo-aimp
