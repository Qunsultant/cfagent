### Added

- **A step can start an independent child run (#6394):** a fan-out was always units inside ONE run, so one unit's failure failed the run. `child.run` is a reserved engine step that dispatches an independent run of another job — its own run id, instance row, lifecycle and failure — through the same `runJob` the doors use, and the parent records the child's id and reacts to its outcome by a named rule. `onFailure` (`fail` | `continue`) is required, so a parent never silently proceeds past a failed child; a child naming the parent's own job refuses by name (one live run per instance); a child that outlives the step's bound reads as `timed_out`. Unlike the wait stages the step IS journaled, so a replay reads the recorded child id instead of starting a second child, and the child links back through the run record's `originRunId` — a first-class run in the recorder, not a hidden unit. Pins: `tests/job_child_runs_6394.test.ts`; the engine reference (§3.2) states the primitive.
