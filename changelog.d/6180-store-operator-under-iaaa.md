### Fixed

- **Store-operator is now an IAAA membership, not a second login-keyed admin gate (#6180):** the `store-operator` role joins the role catalog as a tenant-scoped binding (Q9 90-day default expiry, revocation, audit); one gate helper (`src/security/storeOperatorGate.ts`) serves all six gate sites (data-lifecycle, DLQ, channels, tenants, payments, `/operators`); `/operators/add` and `/operators/remove` mint and revoke memberships through the grant route's machinery (tenant-admin grant power required, SELF_GRANT kept); platform bootstrap initialize and tenant bootstrap migrate every env-list + store-list login to a membership via the alias record (lossless — an unresolvable login keeps access through the deprecated fallback until it signs in); the founding admin gains store-operator alongside tenant-admin at tenant bootstrap, so a fresh platform still bootstraps. The env list (`COMMERCIAL_STORE_OPERATORS`) and the store operators list are deprecated, never deleted — their removal is follow-up #6185. A bare store-operator can no longer add/remove operators (grant power is a tenant-admin function); add/remove no longer 503 on an unbound AGENT_DB (503 only when the membership store is unbound).
