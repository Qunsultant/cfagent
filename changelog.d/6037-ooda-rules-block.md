### Added

- **The OODA strategy rules are one declared, validated, versioned block (#6037 (a)):** twelve numbers that decide which structures are built, how candidates rank and which thesis wins now have a single declaration — key, bounds and default — in `src/config/researchRules.ts`, with `ResearchConfig.rules` persisting the stored overrides as JSON in the existing `research.*` settings block (empty = every declared default, which is exactly today's literal, so the release is behaviour-neutral). `validateResearchRules` merges a stored block over the defaults and refuses **by name**: an unknown rule, a non-number, a value outside its declared range, an inverted DTE window, scoring weights that do not sum to 1, and an inverted breakeven band. A stored-rules change without a `rulesVersion` bump is refused atomically — the version is the audit key a report names, not a label — and the report snapshot already carries the block plus the version, so a run is reproducible from its own evidence. Slices (b) structure selection and (c) scoring/thesis move the pipeline's literals onto this seam next, each pinning "same output at default values"; nothing in the decision path changed here. #COO-spr9
