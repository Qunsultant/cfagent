### Added

- **Agentic scheduling (#3121 Phase 3, #3122):** one agent-facing schedule-management capability (create, update, pause, resume, trigger, delete, list) in `src/services/agentScheduleCapability.ts`, tenant-scoped to the per-login instance, operating on the existing stores through injected adapters (SDK schedules + goal schedules; re-pointing at #3123's unified store is follow-up, not a second path). Every action is PDP-enforced through the same compiled policy + membership PIP as `evaluateRoutePep` (via `authorize()` with the alias-resolved principal — the session precondition of `evaluateRoutePep` cannot be met inside the DO routes), and every action writes a consolidated run-ledger row with agent identity / tenant / schedule. Consequential schedules (external send, spend over the owner-configured budget threshold, frequency below the owner-configured floor, trading) are approval-bound before they arm: refused with `approval-required` plus a pending-approval record, never armed; approval is decided at `POST /api/schedules/approvals/:id/approve|reject` (SDK, PDP-checked for `action:approve`) and `POST /api/schedule/goals/approvals/:id/approve|reject` (goals, Worker-side `evaluateRoutePep` for `action:approve`), arming under the original requester's principal. Thresholds are owner-configured (`AGENT_SCHEDULE_BUDGET_THRESHOLD_CENTS`, `AGENT_SCHEDULE_MIN_INTERVAL_SECONDS`); unset means fail-closed (the class is approval-bound). The NLQ allow-list hole is closed inside this build (F1): `scheduleData.callback` is now an enum of the reminder + the four creatable callbacks, enforced in the schema and in the executor, and NLQ schedule actions route through the capability on the orchestrator, chat-fallback, async-jobs, and MCP paths. Descriptor-only goal operations are excluded from agent scheduling (F2) and refused honestly — no execution is wired silently. Two agent channels: NLQ-mediated requests and direct agent tools (A2A `schedule.*` on the orchestrator card; the six goal A2A ops gain F2 classification). A2A schedule actions carry no principal login today, so they refuse fail-closed until the principal-carrying envelope lands (#4143); the approval UI is #4142. Agent-created schedules render in the schedules and goals surfaces with an Agent badge (provenance `origin: "agent"`). Tests: `tests/schedule-3122-agent-capability.test.ts` (3122-P01–P17, P14b–P14c), NLQ F1 pins in `tests/nlq_scheduling.test.ts`, A2A pins in `tests/a2a_orchestrator_dispatch_p2223.test.ts` and `tests/a2a_remaining_handlers_p2223.test.ts`. No file deletions. #3122
