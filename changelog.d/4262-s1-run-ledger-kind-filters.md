### Added

- **The one run ledger filters by kind (#4262 S1):** the schedules home runs view (`?tab=schedules&view=runs`) now carries a filter button per run kind — All, Stock, Strategy, Options, Goal, Reports, Workflow, Pipeline, Operations, Other — each with its live count, and each row shows its kind. Runs are classified from the recorded operation namespace (`trading.screen_options` → Options, `trading.screen_stocks` → Stock, pipeline `feed`/`enrich`/`analyze`/`generate`/`deliver` → Pipeline, `chain` → Workflow, `report.*` → Reports, `index.*`/`social.*`/`qa.*`/`resource.*` → Operations, a goal with no family namespace → Goal), and an operation no rule matches lands under **Other** — never dropped, never guessed. The filter set and the default filter are configuration (`RUN_LEDGER_FILTERS`, `RUN_LEDGER_DEFAULT_FILTER`), so a deployment can show fewer buttons or open on one; `?kind=<id>` deep-links the filtered view and an unknown kind falls back to the configured default. Runs stay in the one ledger (`job_run_records`); no second read path is added. #autoclaw-001
