### Changed

- **Paper/live is now a real choice for both brokers (#3272 S4):** `TradingPlatformRegistry.register("alpaca", …)` dropped the `overrideEnv` argument, so the TEST/PROD switch — the only control that names a trading type — could never reach Alpaca; `paper` was inferred from which environment keys happened to be set. The registration and `AlpacaTradingPlatform` now thread the selection through to `resolveAlpacaTradingBase(env, overrideEnv)`, which resolves in a fixed precedence: a deployment pin (`ALPACA_TRADING_TYPE=paper|live`) wins, then the persisted selection (`TEST` → paper, `PROD` → live, the mapping the catalog already declares for every broker), then `ALPACA_BASE_URL` inference, which preserves legacy behaviour for deployments that set only a base URL. The resolver also reports **which** source decided (`pin` | `selection` | `inference`), so status, account mapping and order placement can each state why they are paper or live instead of guessing. A `TEST` selection can never land on a live host even when a live base URL is configured, and a pinned paper deployment cannot be pushed live by a UI click. #ceo-aimp
