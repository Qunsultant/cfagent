### Fixed
- E*TRADE OAuth start failure no longer strands a bare about:blank tab: the pre-opened tab is closed when possible, and otherwise navigated back to the app with an outcome code (etrade_connect_error) whose catalog message renders in the hub banner. The start fetch also has a 30s timeout so a hung fetch cannot strand the tab silently.
- E*TRADE request_token, access_token, and renew upstream failures now surface as AOP outcome-encoded errors (FAILURE_ETRADE_OAUTH_REQUEST_TOKEN_FAILED, FAILURE_ETRADE_OAUTH_EXCHANGE_FAILED, FAILURE_ETRADE_OAUTH_RENEW_FAILED) with remediation; raw upstream HTML/bodies are logged server-side only, never surfaced.
- Blocked-popup banner no longer invalidates the PIN it hands out: its button re-opens the PIN modal bound to the original request token instead of starting a fresh Connect, so a PIN obtained from the banner link still submits.
- The dynamic menu's Connect button for Alpaca no longer fires E*TRADE's OAuth flow: Alpaca gets its own connect entry that verifies the configured API credentials against the existing market-data account route, and Alpaca non-placement read routes return outcome-encoded errors (FAILURE_ALPACA_UPSTREAM) instead of raw provider messages.
