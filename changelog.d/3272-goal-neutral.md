### Changed

- **Goal screening now runs on the selected broker and labels it honestly (#3272 S3):** the goal path built both legs on the E*TRADE client — `createLiveStockScreener(...)` for stocks and `new DynamicOptionsScreener(etrade.client, …)` for options — so a **scheduled** run for an Alpaca tenant screened E*TRADE data under an Alpaca selection. `ScreenerAgent.runGoalScreen` now resolves the tenant broker and, when it is not E*TRADE, builds the legs from that broker's platform: the stock leg is `NeutralMarketScreener` over `platformQuoteSource(platform)`, the options leg is `DynamicOptionsScreener(platformChainSource(platform))`. E*TRADE selections keep the existing engines and the existing seam, unchanged. Provenance is fixed with it: a screening request may name its provider (`providerId`), and the goal run passes `broker-neutral-stocks`, so the result is labelled with the engine that actually served it instead of whichever provider registered first — the report can no longer claim `etrade-yahoo-stocks` for Alpaca data. `ScreeningProviderRegistry.screen` refuses an unknown provider id rather than falling back, and a neutral run with no broker context still answers `no_universe` with a named reason. #ceo-aimp
