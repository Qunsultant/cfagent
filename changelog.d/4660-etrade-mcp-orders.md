### Added

- **E*TRADE joins the chat surfaces that can list and cancel orders (Qunsultant/cfagent#4660):** the broker catalog declared `orders: null, cancel: null` for E*TRADE, so the assistant could see and cancel Alpaca and Public orders but not E*TRADE's — it could preview and place one, then had no way to read it back or call it off. Two tools answer that: `etrade_orders` (`mcp:read`) lists the tenant's orders in the neutral row shape through `platform.getOrderHistory`, with the status filter the sibling tools already take; `etrade_cancel_order` (`mcp:trade`) cancels exactly one order through `cancelOrderRemote` and returns the broker's own receipt, refusing a call with no order id rather than guessing one. Both resolve the tenant's **stored** environment (never a per-call override), so a caller cannot read one environment while the tenant trades in another, and both are registered on the MCP factory, the tool-family record, and the permission map. Cancel-all and per-ticker cancel remain Alpaca-only: E*TRADE has no ladder model to scope them by.
