### Added

- **The neutral stock screen is a real provider, not just a route (#3272 catalogue):** `SCREENING_PROVIDER_DESCRIPTORS` may only name providers that `createDefaultScreeningRegistry` actually builds — the pin that rejected an earlier attempt was right. `StockScreenerFilter` now carries `universe`, so `IMarketScreener.screenMarkets(filter)` can finally say which universe to scan; `NeutralMarketScreener` resolves it through the live listings feed (`resolveUniverseSymbols`), quotes it through the selected broker (`StockQuoteSource`), and runs the unchanged `screenWithQuotes` evaluator. It is registered as `broker-neutral-stocks` (descriptor route `/api/broker/screen`, client endpoint `selected-broker`) **always** — so the table and the registry can never disagree — and refuses with `status: "no_universe"` and a named reason when the run has no broker context, instead of reporting "no matches". A failure of the listings feed is the same named refusal; an over-cap universe is scanned partially and the filter summary says `N of M scanned (bounded)`. The shared stock-filter schema gains `universe`, keeping the type and the Zod mirror in step. #ceo-aimp
