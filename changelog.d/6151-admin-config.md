### Added

- **Nav admin config screens (Qunsultant/cfagent#6151, S4):** per-tenant allowances, per-user allow-lists, and persona-default editing, behind migration 0087 (`agent_nav_tenant_allowances` + `agent_nav_user_allowlists` + `agent_nav_persona_defaults`, D1 + in-memory store ports behind `src/data/navAdminConfigPorts.ts`). New routes under `/api/platform/nav-admin`: config read (scope `platform`|`tenant`, allowances, allow-lists, persona defaults with override flags, and the in-scope member user ids for the picker), tenant-allowance write (platform admin only), user-allow-list write (platform admin any user; tenant admin only their own tenant's users, row tenant derived server-side), persona-default write/reset (platform admin only). The server refuses an allow-list wider than the tenant allowance (`FAILURE_NAV_ALLOWLIST_EXCEEDS_ALLOWANCE`, 403) and refuses a saved-preset apply when saved presets are disallowed for the user (`FAILURE_NAV_PRESET_NOT_ALLOWED`, 403); the availability endpoint caps `visibleTabs` by the allowance and allow-list on every call and falls back to the stored custom map when the active saved preset is disallowed. Admin personas bypass subscription gating and admin narrowing and see the entire menu. The Platform Admin page gains an eighth tab, Nav & Menu Access (`?tab=platform-admin&view=nav-config`), rendering `NavAdminConfigPanel` (primitives only, token-only styling, zero bespoke CSS); saving a row invalidates and re-fetches the shared platform context so the admin's own menu re-reads. New pins: store-contract cap refusal, admin-route authz matrix, tenant-admin scoping, persona-default validation/reset, availability narrowing (allowance, allow-list, saved-preset disallowance, persona-override effective next call), the 8-item platform-admin inventory, and the panel render/save/refusal matrix.
