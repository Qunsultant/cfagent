### Added

- **Nav-availability endpoint + client context store (Qunsultant/cfagent#6151, S1):** `GET /api/platform/nav-availability` resolves the one shared platform context (`resolvePlatformContext`) once per session and returns the effective nav availability computed server-side — `visibleTabs` (top-level ids plus `<parentId>:<subId>` sub-item keys), `availablePresets` (built-in keys), `personaDefault`, `persona`, `tier`. Persona defaults (platform-admin, tenant-admin, paid, non-paid) live in `src/client/nav-config.json`; all four are alltabs-equivalent in S1, so the change is behavior-preserving on day one. The client fetches once at `Chat.tsx` bootstrap through one store (`src/client/platformContextStore.ts`, the F2 one-cache pattern) with the re-fetch seam #6152 needs (`fetchPlatformContext(force)` + `invalidatePlatformContext()` + `usePlatformContext()`); the localStorage map is adopted once as the implicit selection and never written again. Invalidation is wired at the Stripe billing webhook, subscription activation, unlimited-free grant, store-operator grant, role-grants route, and sign-in. New pins: endpoint persona/availability matrix, invalidate-then-reresolve, client store fetch-once/emit-only-on-change, selection ∩ availability merge, and the client context census (shrink-only baseline).
