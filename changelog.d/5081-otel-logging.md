### Added

- OpenTelemetry (OTel) foundation + logging, J1–J7 domain only (#5081, program #5080 S1): the Workers-compatible OTel SDK (stock JS 3.x logs stack: `@opentelemetry/api` 1.10.0 + `@opentelemetry/sdk-logs` 3.1.1 + `@opentelemetry/otlp-transformer` 0.301.2) wired into the ONE structured logger — no new logger, no SigNoz, no ClickHouse, no VPS, no Workers Paid features, no D1 for telemetry. The four-level on/off mechanism, all externalized in `config/otel.json` + env vars and resolved run > session > user > env > config-file > built-in safe default (invalid fails closed to OFF / none / 0 with a coded OBS-1001 message): (1) global master OTEL_ENABLED / OTEL_SDK_DISABLED kill switch, (2) per-signal OTEL_LOGS/METRICS/TRACES_EXPORTER (otlp | console | none; logs is the live signal, metrics/traces resolve to none until S2/S3), (3) per-domain OTEL_DOMAIN_<DOMAIN>_ENABLED with a single AOP gate at the domain boundary (J1–J7 ON; Stock Copilot, IAAA, MCP/A2A, scheduler, payments, market data, platform OFF by default), (4) per-domain level (ALL/ERROR/DEBUG/INFO/WARN/TRACE/OFF) + sampling ratio. Export is OTLP/HTTP (JSON) via a thin exporter over the official JsonLogsSerializer with an injected transport: the Worker-side SDK hands OTLP to the ingestion handler in-process (a real HTTP POST to the Worker's own domain returns Cloudflare 522), and POST /api/otel/v1/logs is a real HTTP endpoint for external OTLP senders (disabled with 404 unless the OTEL_INGEST_TOKEN secret is set; Bearer auth when it is) writing one JSONL object per batch to R2 (REPORTS_BUCKET, `otel-archive/<date>/<id>.jsonl`), falling back to the structured logger (Workers Logs) when R2 is unbound. J1–J7 is instrumented through the engine's existing seams only (runSettledObserver chained after the feed-run observer; the stage-step journal wrapping the identity journal) on the ScheduledAgent host, emitting `job.run.settled` + `job.stage.step.started/completed/failed` through the structured logger with a fan-out sink (Analytics Engine / console AND OTel), flushing the batch at run settle. Why not the stock OTLPLogExporter (no public transport injection, so it cannot reach the same-Worker route) or @pydantic/otel-cf-workers (traces-only; its core 2.x conflicts with the logs stack's core 3.x) is recorded in the PR. Residuals, stated honestly: the 242 raw `console.*` sites outside the structured logger are NOT swept in this PR (the OTel foundation + J1–J7 wiring is this slice; the sweep is follow-on work); the workflow / options / in-memory pipeline hosts are not yet wired (same helper, later slice); the runtime flip without a redeploy (KV/D1 switches + admin UI) is S7/S8; the audit-store routing for config-invalid events lands with S5 (the audit slice owns the audit store).
