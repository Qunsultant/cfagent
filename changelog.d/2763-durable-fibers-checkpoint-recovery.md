### Durable fibers checkpoint recovery (#2763, tracker #2708 item B4)
- `ETradeDurableFiberService` now reads the checkpoints it has always written: a run started with a `runId` loads its latest `FIBER_CHECKPOINT` from the event log on (re)start and resumes, exposing the restored stash on the fiber context (`recovered` / `resumedFromStep` / `restoredStash`) and appending a `FIBER_RESUMED` audit event. Checkpoint event ids for run-identity fibers are session-scoped, so two sessions may reuse the same `runId` in one store.
- `previewDurableTWAP` resumes a TWAP preview plan from its checkpoint: slices the checkpoint proves complete are not re-previewed, and checkpoints now carry the plan fingerprint and the previews so far so a resume can verify both before trusting them.
- A corrupt checkpoint fails loud with `FiberCheckpointError` (`fiber_checkpoint_corrupt`) and a checkpoint written for a different plan fails with `fiber_checkpoint_mismatch` — an unreadable checkpoint is never silently treated as a fresh run.
- `execute_durable_twap` gains an optional `runId` input and reports `resumed` / `resumedFromStep` in its result and its `twap.previewed` audit event. Runs without a `runId` behave exactly as before, and the #135 preview-only invariant is unchanged — nothing is placed or filled.
- Registry truth-sync: the `durable-fibers` tool family stays `degraded` with notes rewritten to the landed state; the Agents SDK conformance matrix fibers cells stay GAP (no agent uses the SDK fiber primitive) with their evidence corrected.
