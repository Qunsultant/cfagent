### Feed-family explicit-symbols feed support (#5954)

- `feed.pull` now serves a symbols-fed run: the step reads the unit's explicit symbols (shard-table row for the unit's shard key, else the flat `params.symbols` list — the bespoke `shardSymbolsFor` idiom) and passes them to the quotes runner as `explicitSymbols`; a `"symbols"` universe with no explicit symbols refuses with `FEED_UNIVERSE_UNKNOWN` before any fetch, and explicit symbols on a non-quotes dataset refuse with `FEED_SYMBOLS_UNSUPPORTED`.
- The quotes runner applies the #4065 membership rule to explicit symbols (extended from the options-chains runner, sharing one `normalizeSymbolsInput` normalizer): all members of the stored list the run resolves ⇒ index-kind subset universe; any non-member ⇒ symbols-kind universe, the symbols used as-is. The membership check is a plain store read — a symbols-fed run never triggers an index refresh. The runner's "stored index list, never an invented one" invariant is honored: explicit symbols are the caller's own list, recorded as their provenance on the artifact.
- Pinned by `tests/feed_symbols_5954.test.ts` (8 tests): a premium symbols command screens exactly its requested symbols with a cold universe store, and ordinary index / sharded-partition runs are unchanged.
