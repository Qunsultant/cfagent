### Added

- **PageTemplate spec + component (#3131, Part of #2150):** the template layer between primitives and pages. New `PageTemplate` in `src/client/components/ui/` renders the seven slots in canonical order — header, context strip, KPI ribbon, workspace (children), action bar, queue rail — over the kept `PageShell` chrome (title + scope note + loading/error/empty states), with the page/tab/nested hosts preserved via `PageChromeContext`, so the same template renders as a standalone route, as a tab, and nested with zero changes to itself. Slots are props; the organisms that fill them land in #3132–#3134, so until then pages pass their own primitive-built content and the slot order and spacing are already the template's. The design-system doc gains §1.6b (the seven slots + composition rules, including the rule of three at every level) and the §1.7 checklist names `PageTemplate`. First consumer: the risk page (`RiskAnalysisPanel`) renders through `PageTemplate` with no visual change. Pinned by `tests/page_template_3131.test.tsx` (slots order, states pass-through, all three hosts) plus the `ui_primitives_inventory` entry. #cpo-dhmp
