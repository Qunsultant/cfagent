### Added

- **Drivers on the stage-runner contract: resume and a named fan-out cap (#3028, follower of #2601):** `runParentFlow` now builds its run plan from the command and asks the contract which units are outstanding — a resume (`resumeFrom` checkpoint, production adapter `createAsyncJobStageCheckpointStore` #3027) starts only non-terminal units, records the skipped ones as `resumedSkippedUnits`, and a resume whose checkpoint says everything is terminal collates the stored result instead of reporting a false "no shard ran" failure. When a fan-out round defers a tail, the collation carries `fanoutCapReason` naming the deferred units (the tail still runs next round — a pace signal, never a truncation). A first run with no checkpoint behaves exactly as before. Pinned by `tests/driver_wiring_3028.test.ts` (5) plus the contract, seam A/C and five workflow suites (135 tests).
