### Mesh options-strategy door: chat options strategy screening without NLQ (#2581)

- New mesh door command `run_options_strategy_screen` (mcp:write) over a new door-layer service (`src/agents/orchestrator/meshOptionsStrategyDoor.ts`): a chat options strategy screen — universe, catalog strategy type, and structured constraints (maxLoss, minProfit, minRewardRisk, DTE window, thesis, risk profile) — assembled into the options engine's structured filters and evaluated through the existing seam the NLQ `options_opportunities` action dispatches to (`runOptionsStrategyAction` → `UnifiedOptionsService.scanOpportunities`). Direct return (the engine's carriage is an awaited inline scan; no workflow/job), results in the engine's own ranking with the constraint echo, and an empty scan returns the engine's honest `no_opportunities` payload. Identity is fail-closed from the acting-login carrier; an unknown strategy type refuses with the new coded `invalid_strategy_type` door error before any engine call. The copilot no longer deflects strategy screens (e.g. NASDAQ100 bull put credit spreads, max loss ≤ $30, max profit > $0) to the UI: chatPrompt steering names `tool_openaimp_run_options_strategy_screen`, the ScreenerAgent chat-turn census cell and the mesh-door tool family record the door, a golden task drives the reported request through it, and the #1763 tool-attribution audit names the new tool (catalog 82 → 83). NLQ and CHAT_NLQ_MODE are untouched.
