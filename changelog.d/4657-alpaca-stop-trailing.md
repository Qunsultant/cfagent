### Fixed

- **Alpaca STOP, STOP_LIMIT and trailing orders place from the neutral seam (Qunsultant/cfagent#4657):** `placeOrderRemote` used to map MARKET/LIMIT only and refuse the rest with a hand-written sentence, while the provider beneath it has supported `stop`, `stop_limit`, `trailing_stop` and `trailing_stop_limit` all along — and carried `trail_price`/`trail_percent` but **no** `stop_price`, so a stop order could not have arrived at the broker with a trigger on any path. The seam now validates through the `advancedOrders` registry (its first production caller: the registry already states what each type requires per broker) and maps all six types; `PlaceOrderParams` gains `trailPrice`/`trailPercent`; the provider's param list and POST body carry `stop_price`; the `alpaca_place_order` MCP tool gains a top-level `stop_price` (schema, zod, and pass-through) so the tool path can place a stop too; and the HITL `executeOrder` path forwards the stored `stopPrice` and `timeInForce` (#4654/#4656) instead of an empty set. A missing required parameter is a named refusal before any POST, trailing refuses both-or-neither distances, and MARKET/LIMIT bodies are byte-identical to before. Extended-hours still requires a limit order.
