### Added

- **Schedule watchdog: a missed firing is now detectable (#3788, sub-issue of #3781):** a schedule/goal/task that silently never runs is flagged instead of reading "never" in a panel. Pure core `src/services/scheduleWatchdog.ts` + `previousCronTickMs` in `src/schedule.ts` (mirrors `isDue`'s matching rules, so the never-due opportunity-hunt quirk cron is never flagged) + grace config `MISSED_SCHEDULE_GRACE_MINUTES` (default 60 min, `0` disables; no production value set). Goals: `ScheduledAgent.onCron` runs the watchdog after the due-goal loop — every finding emits all three signals, claim-first: a runs-ledger record (outcome `skipped`, `missed-fire: ...`), a durable audit event (`schedule.goal.missed_fire`, code `missed_fire` / `invalid_cron`), and a Slack alert through the existing `postSlackText` seam (catalog template `missed_schedule_alert`); plus a per-tick heartbeat ledger row so no heartbeat in 24h means the tick path itself is dead. Durable schedules: `watchdogMissedSchedules` on the same 15-minute sweep tick as #3784 (one tick, two consumers), watching every callback with a ledger record; unrecorded callbacks are skipped and counted, never flagged on evidence the watchdog cannot see. Copilot Think task: non-declaration audits `stock_copilot.not_declared` with cause class (`flag_off` / `no_login_context` / `context_error`, deduped on cause change or 24h), the no-SQL early return audits `stock_copilot.no_sql_storage`, handler failures audit `stock_copilot.cycle_failed` with an error code instead of being swallowed, and every firing is recorded in the runs ledger (`ok` → success, refusals → skipped). Internal-only callbacks (`executeAsyncJob`, `expireStaleOrderDraft`, `collectIvHistory`, `autoRenewETradeTokens`) now record their own runs via method wrappers, closing the #2964 carried gap; the trigger route treats them as self-recording so manual triggers record exactly once. Framework sweep callbacks remain the named gap (no per-run record; observable via their effects + heartbeat). The #1819 resource goals are covered by the same mechanism, proven in test with a `resource-daily-rollup` id. Durable doc: `docs/architecture/security/schedule-watchdog-3788.md`.
