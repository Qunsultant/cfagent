### Changed

- **Production OODA stage dependencies in JobPipelineWorkflow (#6092):** `createWorkflowResearchStepDeps` composes every stage through the owning Orchestrator DO — feed/enrich via `runResearchStage`, analyze/generate/deliver via `runResearchAndPublish` with the stage selector, evaluate via `runResearchEvaluate`. The workflow `research:<runId>` definition now executes the same six stages as the API path, with owner, broker, mode and run id preserved; a missing dependency throws a coded stage error.
- **Durable stage hand-offs across workflow resume (#6093):** the enrich step output now carries the feed output, and analyze reads both from the engine-persisted step output (`ctx.input`). The production pipeline no longer consults the process-local hand-off maps; `requireStageInputs` makes a workflow-resident analyze with a missing feed/enrich artifact fail `research_stage_input_missing` instead of silently re-fetching. The maps remain only for legacy direct callers and are marked deprecated in place.
- Tests: enrich hands the feed forward; workflow mode refuses missing inputs; analyze receives both persisted outputs; the workflow deps builder forwards each stage to the door. #CAIO-quns
