### Fixed

- **A bot-API Slack leg resolves a channel instead of posting without one, and `SLACK_WEBHOOK_URL` is finally deployed (#3980).** `sendTransactionSnapToSlack` and `captureAndSendToSlack` posted `channel: options.channel` straight to `chat.postMessage`, and the callers (`browser_snap_transaction`, `browser_capture_page`) often pass none — with only `SLACK_BOT_TOKEN` configured, Slack rejected the post and the operator saw a Slack API error rather than a configuration one. The channel now resolves the way the trading and screener paths already do (caller → `SLACK_CHANNEL` → `SCREENER_SLACK_CHANNEL`), travels in the payload and in the returned result, and the bot leg refuses **before** calling Slack with the named `slack_channel_not_configured` error when nothing resolves. The webhook and cfpay legs are unaffected — a webhook ignores the field. Separately, `SLACK_WEBHOOK_URL` was read by three services but never in the deploy sync list, so setting it as a GitHub secret changed nothing; it now ships as an eighth `optional_secret` alongside the rest of the Slack set.

- **`SLACK_CHANNEL` is deployable, and the two channel names are typed (#3980).** The fallback needs a destination that can actually be set: `SLACK_CHANNEL` now ships from the GitHub secret of the same name as an `optional_secret`, and both it and `SCREENER_SLACK_CHANNEL` are declared on `Env` instead of being reached through a cast.
