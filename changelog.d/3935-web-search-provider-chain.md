### Changed

- **`web_search` runs a provider chain, free/keyless first (#3935).** The seam had one provider — Brave — and failed loud until `BRAVE_SEARCH_API_KEY` was set; the key was never set, so `web_search` resolved `unavailable` everywhere. Providers now compose on the same seam: **SearXNG** (JSON API, opted in by `SEARXNG_BASE_URL`, skipped when unset), **DuckDuckGo** (the keyless HTML results endpoint — no key, no configuration, so the tool answers out of the box), then **Brave** (when keyed). `WEB_SEARCH_PROVIDERS` sets the order and subset (default `searxng,duckduckgo,brave`; the legacy `WEB_SEARCH_PROVIDER` still selects a single provider). A provider failure — network, HTTP, bot-check page, unparseable payload — falls through to the next and the outcome names the provider that served. An empty chain fails `web_search_provider_not_configured`; an exhausted chain fails `web_search_all_providers_failed` carrying every attempt's code and reason. An honestly-empty result set from a provider that answered is still a real `count: 0`. The result contract, the MCP command, and the PortThink tool consumers are unchanged; the `webSearch` manifest entry loses its `BRAVE_SEARCH_API_KEY` prerequisite and the registry family moves from `degraded` to `live`.
