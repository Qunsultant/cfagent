### Screeners UI parity: delivery/report fields on the Stocks one-shot run + full-parameter Options Research one-shot form (#2545)

- Stocks panel one-shot run gains the scheduled "Stock Market Screen" job's delivery fields — Slack push + channel, email recipients, webhook URL, and a PDF report toggle — carried as a delivery envelope on the manual screen request (the schedule payload's own field names), split out of the engine filter by `parseStockScreenRequest`, stamped onto the run result by the `/etrade/screen` route, and projected by `screenerOutcomeFromRunResult` into the same follow-up delivery bridge the scheduled path uses (per-task channel overrides + an explicit-selection channel allowlist; `generatePdf: false` drops report artifacts from the delivery projection only). Callers that send no delivery fields get today's behavior exactly; the Schedules Trigger path is untouched.
- Options Research gains a full-parameter one-shot run form in its schedules mode: universe / maxItems / thesis / risk profile plus the delivery fields, defaulting to the production "Options Market Screen" parameters (NASDAQ100 / 100 / bullish / balanced). The payload is built by the schedule builders (`buildOptionsRunNowPayload`), validated through the shared criteria check, and submitted to the schedule's own trigger route (`/api/schedules/trigger-options-analysis` → `autonomousOptionsAnalysis`, stamped manual server-side).
