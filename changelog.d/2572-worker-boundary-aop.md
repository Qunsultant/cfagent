### Fixed

- Worker error boundary (issue #2572): an error escaping Worker fetch no longer returns the hardcoded `internal_error` body ("Internal error. The failure has been logged."). It now returns the outcome-catalog body `[FAILURE_UNEXPECTED_ERROR] An unexpected error occurred. Our team has been notified.` via the single resolver (`codedMessage` over `src/outcomes/outcomeCatalog.json`), with the original error text in logs only. The KV-quota path is unchanged (503, `kv_quota_exhausted`, Retry-After 30), as are the Response-as-control-flow passthrough and the no-store / Retry-After headers. This affects every Worker-fetch surface, not just discovery, because the boundary wraps all of Worker fetch; the discovery routes and panels that render `err.message` verbatim remain a named follow-up.
