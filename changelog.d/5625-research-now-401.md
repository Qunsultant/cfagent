### Fixed

- **"Run research now" showed a JSON parser error instead of an auth message (#5625):** `POST /api/research/run` answered a bare-text 401 (`Unauthorized`, `text/plain;charset=UTF-8`) from the generic `/api/*` forwarder (`src/server/routes/core.ts:204`), and the panel called `res.json()` before checking `res.ok` — so the user saw `Unexpected token 'U', "Unauthorized" is not valid JSON` and no way to tell an expired session from a crash. The forwarder now answers `{"code":"UNAUTHORIZED","error":"… sign in again …"}` with `application/json`, and all five panel calls go through one `readJson` helper: 401 → "Your session has expired — sign in again, then retry", non-JSON error → `HTTP <status>: <first line>`, non-JSON success → a stated mismatch rather than a parse throw. Pinned by `tests/research_run_401_5625.test.ts` (the forwarder's 401 is JSON with a code) and `tests/research_runs_panel_401_5625.test.tsx` (plain-text 401, JSON 401, and a 502 HTML body each render the right message and never the parser error). #clo-arsi
