### Fixed

- **Account-binding saves from Settings no longer always fail (#6225):** the selector's `PUT /api/broker/account-binding` (save and registry patch) carried no `X-CSRF-Token` header, so the #3113 CSRF gate rejected every cookie-authenticated save with 403 `csrf_invalid` before any route work ran — for the PA dashboard number and the correct UUID alike. Both PUTs now wrap their init with `withCsrfInit`, the pattern `switchAccountBinding` already uses. A failed save/patch now also surfaces the server's coded reason (`error` / `code`) instead of only the generic "Failed to save account binding." — the 403 body, the validated-path failure, and the plain-upsert failure disagree on field names, and the UI handles all three. No gate change; other brokers/scopes unchanged. #CAIO-quns
