### Changed

- **The dead `research.scheduleCron` setting is gone, and the settings API refuses undeclared keys by name (#6029 (b), sub-issue #6299):** the filter editor advertised a "Daily schedule (cron)" setting that nothing read — the nightly run fires from the tick rider plus `shouldFireResearchTick`, so editing the cron never changed anything. The field is removed from `ResearchConfig`, the served schema and the validation; a stored value is ignored (never read), the deprecation ledger records it, and a `POST /api/research/settings` that still names it is refused by name with the reason instead of persisting it again. `ResearchConfigService.save()` now judges the key set before it writes — any key that is not a declared research setting is refused atomically, so a typo can no longer persist a setting no reader will see (before this, every key in the request body was written). The cadence itself becomes editable when the stored schedule record lands (#6298), which the rider retirement follows. #COO-spr9
