### Added

- **One whole-set vocabulary for what a job may select (#5515):** `config/vocabulary.json` is the one list per axis — providers, datasets, universes, sectors, exchanges, brokers, assets, modes — and `src/config/vocabulary.ts` is its one validated reader. A value is added as data (one entry), never as an engine code change; an invalid definition throws and the previous registry stays in force. `resolveJobSubset` answers what a job actually runs against: declared values resolve (aliases in, canonical ids out), absent axes take the externalized defaults (`alpaca` / `paper` / `equity` / `nasdaq100`), and axes a job does not name stay undeclared instead of being invented. The two conflations the engine carried are declared and refused by name with a pointer: `TECH` is a sector (`sector-information-technology`), `nasdaq` is a data provider. The universe axis is one id space over the screener sets and the stored index lists, and sector-as-list universes are derived from the sector axis so a sector cannot be in one list and missing in the other. Existing constants still hold today's values — pinned — so nothing resolves differently while the consumer surfaces (chat #5500, UX #5965) move onto the reader. #CAIO-quns
