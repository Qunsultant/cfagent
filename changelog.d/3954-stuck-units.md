### Added

- **Stuck units are detected, reaped and surfaced — in the engine (#3954):** a unit that started and never progressed was invisible: the per-unit `timeoutMs` race only fires for work still awaited, and the stale-running sweep lived on the async-jobs/screener side, so a pipeline stage could sit `running` forever with nothing surfacing it. Every running unit now carries `heartbeatAt` on the stage checkpoint (written at the running transition, refreshed at every step boundary), and `sweepStuckUnits()` reaps a unit whose stamp is older than `pipeline.stuckUnitAfterMs` (default 30 min, clamped [1s, 24h]): the unit is marked failed with `job_unit_stuck`, a `failed` stage action names how long it was silent, and the run settles through the SAME path as an orphaned run (`settleRunningInstance`, #4002) — one settle, two triggers, no per-family bolt-on. Additive by contract: terminal units are never reaped, a unit with no readable liveness is left alone rather than reaped on no evidence, and a checkpoint written before the field existed stays sweepable via `updatedAt`/`startedAt`. Pins: `tests/job_stuck_units_3954.test.ts`; the engine reference (§3.9) states the capability.
