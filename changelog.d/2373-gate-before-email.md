### Changed

- **Gate-before-email for manual stock screens (#2373 S1b):** the paid seam now asks the payment gate whether the run is covered (free-run allowance, approved grant, subscription included runs, pack/code balances, credits) BEFORE any checkout email is demanded. A covered run starts with no email at all; a run refused at the approved-free quota cap answers the gate's 402 directly, also with no email demanded; only when the gate says payment is actually needed is a checkout email demanded (400, code `checkout_email_required`), then the payment workflow. The coverage probe is read-only — the workflow's own gate check remains the single consuming decision. The Stock Hub no longer blocks the run client-side on a missing email, shows the remaining free runs (`N free runs remaining this month`, 10/product/UTC-month, automatic) while monetization is on, and maps the 400 contact demand to the email prompt with a retry action. Flag OFF behaviour is unchanged.
- **Paid-seam provider carry (#2373 S1b, F9):** the paid seam stamps the tenant-resolved provider into the paid flow and refuses with a coded 409 (`FAILURE_PROVIDER_MISMATCH`) when the route's implied provider differs from the tenant's stored data-provider selection — no fallback provider is used, and an unconfigured tenant (no selection stored) passes. The stored broker rides as provenance only when one is stored. The premium stock-signals fulfilment no longer hardcodes `"yahoo"`: a stored `yahoo` selection stays `yahoo`, a stored `etrade` selection or no selection stored omits the provider (the engine defaults), and any other stored provider is refused with a plain error — no fallback, no fabricated signals.
