### Fixed

- **Public.com cancel is paper-gated and its receipt is truthful (Qunsultant/cfagent#4650):** `PublicTradingPlatform.cancelOrderRemote` now runs the same `FAILURE_PUBLIC_NO_PAPER_MODE` gate placement already had *before any MCP call*, so a TEST-mode cancel can no longer reach Public's one live endpoint and cancel a real order. In PROD the receipt is derived from the broker's own answer — success requires an explicit `success: true` or a cancellation status word; a refusal, an error, or a payload with no signal at all reads as *not cancelled*, with an "unconfirmed" message instead of the previous unconditional `success: true`. The neutral cancel route and the `public_cancel_order` MCP tool surface the receipt unchanged (409 on failure), so UX, API, and MCP agree. The `FAILURE_PUBLIC_NO_PAPER_MODE` catalog copy widens from "cannot be placed" to "cannot be placed or cancelled" (same code, no new outcome).
