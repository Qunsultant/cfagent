### Added

- **Coded stage messages, externalized stage config, one advice pass per stage (#3075, #3069 R7/R6):** stage failures used to be prose — countable by nobody, alertable on nothing, translatable by hand. `STAGE_MESSAGE_CODES` is now a closed set with a catalog entry per code (text, remediation, severity: poison / budget / data), and every dead-letter path in `stageReportConsumer` emits a code first (`STAGE_WRONG_TARGET: …`), with the existing vocabulary ("poison", "retry budget exhausted") preserved inside the rendered text so operators' greps keep working. `resolveStageConfig` externalizes stage budgets — `WORKFLOW_STAGE_MAX_ATTEMPTS` plus per-stage `WORKFLOW_STAGE_MAX_ATTEMPTS__<STAGE_ID>` — with code defaults and a **loud refusal** (`StageConfigError`, code `STAGE_CONFIG_INVALID`) on a bad value, because a typo'd budget must never look healthy. `withStageAdvice` is the single pass every stage body runs under: it records duration and the coded verdict, then rethrows the original error unchanged, so retry/DLQ behaviour is identical to before. Ten pins cover the catalog, the config precedence and refusal, and the advice's neutrality.
