### Fixed

- **A merged PR closes its issue whichever repository slug it names (#4565):** GitHub resolves a closing keyword only against the repository the PR lives in, so `Fixes OpenAIMP/cfagent#N` — the repository's former name, which §9 and the Policy Gate both accept — merged with the issue still open (PR #4560 / #4532). A merge-time reconciler (`.github/workflows/close-merged-issues.yml` + `scripts/ci/closeMergedIssueRefs.mjs`) now parses the PR body and title for closing keywords naming **either** `Qunsultant/cfagent#N` or `OpenAIMP/cfagent#N` (any case, or a bare `#N`), comments the merge commit and the PR on the open issue, and closes it. Any other `owner/repo` is ignored; a closed-but-unmerged PR does nothing; an already-closed issue is never re-closed or re-commented, so a re-run is a no-op; and a `workflow_dispatch` entry replays a merge that was missed. The grammar is the Policy Gate's own (same verbs, same slug set), and gitops §17 now states the accepted forms and points at the mechanism — which is the auto-close reconciliation §17 described but had never implemented. #autoclaw-001
