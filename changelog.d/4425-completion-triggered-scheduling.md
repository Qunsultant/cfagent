### Added

- **Completion-triggered scheduling (#4425):** a job can now be fired by another job's (or stage's) completion. The binding lives on the target job's own raw config under `completionTrigger` — `source.jobId` and/or `source.stage`, the terminal `state` it fires on (`completed` default, `failed`, `cancelled`, `any`), and an optional `targetStage` — so it is stored durably through the same `defineJob`/`configureJob` path as every other job setting, with no second table and no parallel schedule model. The **`job-pipeline-events` consumer is wired for the first time** (`createJobPipelineEventsHandler` was defined at #3543 and never instantiated): a terminal job event records the completion on the ScheduledAgent and then fires every matching target through the same control plane an ordinary run uses; a terminal stage event persists (#4360) and fires stage-scoped bindings. A self-trigger is refused by name, a malformed binding is reported rather than ignored, and a target that cannot fire (already running) is reported with its reason — a chained schedule that silently does not run is the defect this closes. `wrangler.jsonc`'s consumer comment now states it is wired. #autoclaw-001
