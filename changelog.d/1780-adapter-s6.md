### Added

- **ApprovalWorkflow port (#1780, parent #1717 Adapter S6):** one `ApprovalWorkflow` port (start/decide) for trade approval, with the Cloudflare Workflows implementation behind it (`src/services/approvalWorkflowPorts.ts` + `src/services/cloudflareApprovalWorkflow.ts`). Both workflow operations in `TradingAgent` (`startTradeApproval`, `decideTradeApproval`) now go through the port; the binding name, params, event type and payload, agent-origin instance naming (`trading:<login>` / bare `trading` per the S5 gateway), and SDK workflow-id generation are unchanged, and the trade-approval HITL gate (input validation, binding-presence guard, owner-login fail-closed, blocking decision audit before delivery) still runs before either port call exactly as before. No behavior variant is introduced, so no config switch: scoped adapter selection resolves to the built-in Cloudflare default, and no caller can configure away an enforcement through this port. Pinned by `tests/adapter-s6-1780.test.ts` (TDD Red: module-missing, before the implementation) with approval semantics still pinned by the existing approval suites. #CISO-bhdm
