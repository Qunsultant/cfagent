### Fixed

- Scheduled screener jobs are broker independent (#3655): the scheduled auth guard resolves the tenant broker first (fail-closed) and verifies that broker's credentials — an Alpaca-broker tenant's scheduled runs no longer hit the E*TRADE preflight or fail with an E*TRADE-named error; the sharded options executor resolves its chain source from the tenant broker (Alpaca platform chain source / E*TRADE client / `provider_unsupported`); the scheduled stock path resolves its provider from the tenant's `dataProviderId` at run time (Alpaca quotes via the existing Alpaca adapter) and the silent Yahoo fallback on a blocked run is removed — a blocked provider fails loud and coded. Schedules record broker + data provider + mode (live/paper) at creation, the new-schedule dialog shows Broker and Mode as visible fields, and Schedules home, schedule detail, the Schedule Run Ledger, Workflow Runs, and the discovery run record display/carry them. The run record carries the EFFECTIVE mode (`mode` + `isLive` + resolver source `pin`/`selection`/`inference`): an Alpaca deployment pin (`ALPACA_TRADING_TYPE=live`) beats a TEST schedule, so a pinned-live run records `live` with source `pin` and can never claim "paper" while executing live (#3668 owns the toggle; this records what it resolves to).
