### Fixed

- **Delivery via channels: the Slack text leg carries the receipt, and transport failures are named (#3950).** A transaction snap routed through cfpay's A2A Slack leg posted only the one-line headline while the webhook and bot-token legs posted the full Block Kit receipt — so a "delivered" snap carried materially less than the caller asked for. The text leg now posts the same fields (status, price/order type, total, broker routing, tx id, timestamp, legs). A failing leg reports `slack_delivery_failed: <detail>` instead of surfacing the transport's raw text, and a cfpay answer with no delivery receipt is reported as **unconfirmed** — `cfpay_no_delivery_receipt`, keeping `no_data_part_in_response` in-band for traceability — rather than as a protocol code with no channel, outcome, or action; a non-2xx answer is `cfpay_http_error`. Both terminal not-delivered messages now name every transport actually checked: `SLACK_WEBHOOK_URL`, `SLACK_BOT_TOKEN`, and cfpay (`CFPAY_OUTBOUND_TOKEN` / `CFPAY_A2A_TOKEN`).
