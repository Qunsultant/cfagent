### Scheduled ticks run under the schedule owner's account tenant

- Tick tenant resolution now derives from the schedule owner's stored commercial account row (`resolveTickTenant` in `src/services/paidScreenSubmission.ts`): the stock and goal tick gates and the flag-OFF workflow command all run under the owner's account tenant, so a deployment whose env default differs from the owner's tenant no longer fails owner ticks closed on the paid-seam mismatch throw. The mismatch throw itself is unchanged — it still guards against cross-tenant billing.
- Schedules with no owner account row take the env default as an explicit, logged fallback (the `schedule.tick_tenant_env_fallback` audit in the tick paths, a structured log in ScheduledAgent), never silent. The free path never fails on an unreadable account store: it falls back explicitly and runs.
- ScheduledAgent's tick-wide tenant context (halt reads in `onCron` and `fireSynthesizedSchedule`, chain/schedule projection) now resolves the deployment default explicitly and logs the fallback when no tenant context is threaded in, instead of stamping a hardcoded literal. Per-goal owner derivation needs an owner on the goal/record schema and is not claimed here.
