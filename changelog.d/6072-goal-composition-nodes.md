### #6072: convert the goal-run composition onto engine nodes (6d-a)

- The goal definition's analyze node now runs the eight-step composition (`goal.quota` → `goal.plan` → `goal.ledgerClaim` → `goal.stockLeg` → `goal.optionsLeg` → `goal.assemble` → `goal.ledgerComplete` → `goal.artifacts`) instead of the single `screener.goal` dispatch: quota is the submission gate (charged as `goalScreen:<runId>`, the port counting a re-delivery once), the plan is the pure `buildGoalScreenPlan` derivation, the ledger claim/complete steps run the #5269 adoption + completion semantics on a D1-resident ledger, each leg dispatch catches its throw as a failed class (#462), the assembly is the extracted `assembleGoalScreenResult` (the #1963 error-status checks + partial contract, verbatim from `runGoalDrivenScreen`), and the artifacts step runs the report tail and builds the analysis output the store stage consumes.
- The ledger is D1-resident: new `agent_screener_task_entries` table (migration 0080) behind `ScreenerTaskStore`, with `D1ScreenerTaskStore` (drizzle D1, upsert on set, `screener:`-namespaced keys matching the DO-storage implementation) and `InMemoryScreenerTaskStore` for tests. The factories wire it from `env.AGENT_DB`; unbound = a named refusal, never a silent fallback to the DO-storage ledger. A goal run's ledger now survives a workflow eviction replay (an active record is adopted, a terminal record short-circuits as a duplicate).
- The composition steps resolve their production defaults from the agent port (new methods `chargeGoalScreenQuota`, `runGoalStockLeg`, `runGoalOptionsLeg`, `generateGoalScreenArtifacts`, reusing the private dep builders `runGoalScreenOnEngine` used); `runGoalScreenOnEngine` and `screenGoalStage` are never called on the path. The leg functions `runGoalStockLegViaWorkflow` / `runGoalOptionsLegViaWorkflow` are exported for the 6d-b/6d-c re-points.
- `JobStageSpec` gains an optional `steps?: string[]` (validated by `resolveStage`, which previously dropped it); the builder runs every declared step on the node. The goalScreen spec is v2 with the composition on its analyze stage; its legacy single `step` stays `screener.goal` for old stored definitions.
- Tests: the 4192 goal-leg dispatch tests and the 5873 goal definition/dispatch tests are re-pointed onto the composition (injected leg/quota/ledger deps; the #4279 test now pins the agent-method defaults). The fixtures' scenarios are real now (`buildScenario`, directional/bullish) — the old literals (`goalKind: "growth"`, direction `"long"`) were never valid ScenarioDefinitions and only survived because the injected fake runner never called `buildGoalScreenPlan`.
