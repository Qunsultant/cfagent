### Assurance retrieve-by-reference parity on status (#2197 follow-up)
- **Assurance retrieve-by-reference (#2197 follow-up)**: the status endpoint now accepts a stored `checkoutId` query param as an explicit session-lookup key, with the same precedence as check-payment (`sessionId` wins, then `checkoutId`, then the workflow id). Previously status built its lookup record from the `sessionId` query param alone, so a stored `checkoutId` reference (the card checkout join key, i.e. the Stripe session id) was silently ignored and the lookup fell back to the workflow id. Check-payment already honored both keys and still binds every caller-supplied reference back to the run (complete + paid + `client_reference_id` equal to the workflow id) before delivering `payment_verified`; a misbound stored reference delivers nothing. No flag change, no price change, no activation.
