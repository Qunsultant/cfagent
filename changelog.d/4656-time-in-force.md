### Fixed

- **The ticket's time-in-force now reaches the broker (Qunsultant/cfagent#4656):** the value the order ticket has offered since #4573 used to die at the server — the preview route never parsed it, `mas_trades` had nowhere to keep it, execute forwarded nothing, E*TRADE hardcoded `orderTerm: "GOOD_FOR_DAY"`, and Public sent no TIF at all. Now one canonical vocabulary (`src/trading/timeInForce.ts`, lower-case `day|gtc|ioc|fok`) is parsed and normalized by the preview route (an unrecognised value is a named 400), refused for any value the broker's own capability matrix does not list (the same table the ticket renders), stored on the draft in the new `mas_trades.time_in_force` column (catalogue CREATE + guarded ALTER), and forwarded at execute to `placeOrderRemote` on both the neutral and legacy routes. E*TRADE maps `day/gtc/ioc` onto `GOOD_FOR_DAY`/`GOOD_UNTIL_CANCEL`/`IMMEDIATE_OR_CANCEL` in preview and placement; **FOK is no longer offered for E*TRADE** because this client has no verified FOK term, so the matrix stopped advertising it. Public, whose hosted schema is unverified for TIF (matrix ❓), refuses anything but the default by name (`PUBLIC_TIME_IN_FORCE_UNVERIFIED`) instead of placing a silent day order. Alpaca already honoured the value at placement and now actually receives it. Schema pins regenerated in the same change.
