### Added

- **An analytics lake behind a port, off by default, with the yahoo/technicals archive as its first producer (#5814, parent #5813):** Cloudflare Basin (Pipelines → Iceberg on R2 → Basin SQL) is now reachable as a *third tier* — an append-only history store for questions the pruned tables cannot answer — without touching D1 or Durable Object SQLite. `AnalyticsLakePort` is write-only (`append`), with a Basin HTTP-ingest adapter, an in-memory adapter that doubles as the inert default, and `createAnalyticsLakePorts` as the single env→adapter seam. `ANALYTICS_LAKE_MODE` (default `off`) is externalized alongside the endpoint, token, dataset allowlist and table; `basin` without its endpoint/token resolves to `off` **with a named reason** rather than a silent void. The cross-cutting concern lives in one AOP aspect, `withLakeArchive`, which decorates the existing `FeedDatasetStore` at the composition root: it archives only the configured datasets, runs *after* the inner write succeeds, carries counts and provenance (never the payload rows), and **never throws** — a lake outage logs `analytics_lake_archive_failed` and the feed run stands on its own records. Default deployment behaviour is byte-identical to before. #ceo-aimp
