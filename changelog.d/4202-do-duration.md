### Changed

- **DO duration: the chat await is bounded, and the no-op keep-alive timer is gone (#4202):** Durable Object duration bills wall-clock residency, and the Cloudflare finding on #4202 put the account ~42,000 GB-seconds over its allotment. The sharpest in-code contributor was the chat screen/payment await: a 2s poll loop held **inside the OrchestratorAgent request for up to fifteen minutes**, per run, with the same `15 * 60_000` literal copied into both `src/agents/orchestrator/meshScreenDoor.ts` and `src/agents/orchestrator/nlqPorts.ts`. Both now resolve one shared budget from the new `src/agents/orchestrator/chatAwaitBudget.ts` — default **120s**, hard ceiling equal to the default (configuration can shorten the wait, never restore the long one), operator lever `CHAT_AWAIT_BUDGET_MS` (floor 5s). The existing honest "did not complete within the chat await window" result and the run link are unchanged, and a run longer than the budget keeps executing on its workflow. Separately, `ETradeDurableFiberService.keepAlive()` armed a 30-second `setInterval` whose callback did nothing — a live timer is exactly what makes a Durable Object ineligible for hibernation — so the timer is removed and the disposer contract kept. Checked and unchanged: quotes WebSocket upgrades forward to `TickerAgent`, whose SDK `accept` routes to `ctx.acceptWebSocket` (hibernation-capable), and the voice socket is accepted in the Worker rather than in a Durable Object. Pinned by `tests/chat_await_budget_4202.test.ts` (7 tests, including a source pin that no copied literal can restore the fifteen-minute window). #autoclaw-001
