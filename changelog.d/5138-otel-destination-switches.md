### Added

- OpenTelemetry destination switches — every observability/logging destination individually on/off (#5138, observability program #5080, S1 extension of #5081): one switch per destination in `config/otel.json` + env vars, resolved run > session > user > env > config-file > built-in safe default OFF (invalid fails closed to OFF with a coded OBS-1001 message): Analytics Engine sink (`OTEL_DESTINATION_ANALYTICS_ENGINE_ENABLED`), R2 OTLP export (`OTEL_DESTINATION_R2_ENABLED`), console sink (`OTEL_DESTINATION_CONSOLE_ENABLED`). Config-file defaults are all ON, preserving the current behavior. `createObservabilitySink` (the composition root) respects them: AE off means never write to it (fall back to console only if console is on; if both off, the event is dropped — logging never fails the caller). The OTel transport respects the R2 switch (R2 off = no R2 write; ingestion falls back to the structured log). Workers Logs is documented as the deploy-time `observability.enabled` switch in `wrangler.jsonc` (set false to silence it entirely; currently true at 1% sampling, `persist: false` per #4131) — the Worker cannot flip the Cloudflare platform log pipeline at runtime, and no runtime switch is pretended for it. The five-level on/off mechanism (master, per-signal, per-domain, per-domain level/sampling, per-destination) is recorded in `docs/OBSERVABILITY.md` §6. A circular-import hazard found while wiring the sink (the otelModes module logger called `createObservabilitySink` at module top level, before `OTEL_FILE_CONFIG` was initialized) is fixed by making that logger lazy. The runtime (no-redeploy) flip is still S7/S8.
