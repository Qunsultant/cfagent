### Added

- Universal retention for the #1717 program (#1766, F-37 / F-38 / F-41 / F-58): the shared retention registry from #1765 (`src/privacy/privacyDsar.ts`) now covers every table in the recorded decision inventory (mas_* / agent_* / research / screener stores) with a per-table rule — bound (age window, plus row cap where one applies) or KEEP-with-reason — and an enforcement status (enforced / at_source / carried, with the blocker named when carried). No second retention mechanism: this slice extends the shared registry and wires around it. Automated DO SQLite snapshot export to R2 (nightly, riding the existing 0 4 * * * retention pass as a best-effort leg that never fails the pass; per-table capped dumps with truncation flags and content hashes under `snapshots/orchestrator/<date>.json`, complementing Cloudflare PITR's 30-day whole-DB restore — see the recovery procedure in `docs/architecture/retention/retention-1766.md`). Automated orphan sweep on the same nightly pass: `reports/*.json` bucket objects with no `mas_reports.body_r2_key` row are reported every night and deleted only when the operator sets `RETENTION_ORPHAN_SWEEP_DELETE` to exactly `"true"` (report-only by default, fail-closed; dangling rows are reported, never deleted). Purge runs are audit events: every AgentDB purge via `POST /api/retention/purge` appends a `retention.purge` IAAA audit event (`auditOk:false` on the report when the append fails), and the nightly sweep/snapshot legs write their own `mas_events` audit rows. Pinned by `tests/retention_1766.test.ts` (TDD red-first, 17 tests). Honest boundaries, named not hidden: two #1765 registry claims are corrected (mas_messages is 90d, not 30d — the nightly pass defaults to 90d and the UI advertises 90d; correcting the declaration changes zero runtime behavior since no enforcement reads the registry); `screener_runs` is a logical name whose physical stores already enforce 365d + caps at source, so its declared 30d target is carried pending an owner product decision; `research_runs` at 30d is carried, not enforced, because the track-record feed reads it directly and pruning would truncate track history; the nightly sweep/snapshot legs run on the shared Orchestrator instance only (per-user instances are covered by PITR, not by these legs); snapshot export is skipped, not faked, when `REPORTS_BUCKET` is unbound. No production switch value set; no endpoint removed; no code path deleted.
