### Added

- **One system-of-record D1 for run ledgers (#4116):** the DO run ledgers (`mas_reports`, `mas_async_jobs`) project into D1 (`agent_reports`, `agent_async_jobs`) behind three independently configurable carriers — queue (`run-ledger.project` claim-check messages on `screener-events`), direct ORM best-effort post, and a one-off sweep backfill (`POST /api/ops/run-ledger-reconcile`) — all sharing one ordering rule (idempotent upsert on the natural key + last-write-wins by source `updated_at`). A pipeline run that generated a canonical report no longer appears as both rows once projected (twin link on the #3121 linkage, resolved only when exactly one candidate run window contains the row). The three read surfaces (`/api/runs`, Workflow Runs, `/api/runs/details`) read D1 alone when the tenant's `readMode` is `d1-only`; unconfigured tenants keep the Option B merged view, and every response carries `ledgerReadMode`. Projection failure never fails the DO write; a tenant with no carrier configured projects nothing and says so by name. Owner scoping is preserved in D1 (`agent_reports.user_login`, migration 0060), pointer bodies resolve from R2 read-only, and the parity suite proves the D1-only lists equal the merged lists modulo linked-twin absorption.
