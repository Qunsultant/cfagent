### Added

- **Append-only job definition history, in both residencies (#5865):** `job_pipeline_definition_versions` keeps every version a job has ever been saved with, while `job_pipeline_definitions` stays the current pointer — so a past run's configuration survives a reconfigure, which is the storage prerequisite for historical replay (#4467). `saveDefinition` appends the row (idempotent per version: the first write for a version wins, so a retry never forks or rewrites history) and `getDefinitionVersion` reads it back, answering `null` for an unknown version rather than today's definition. DO migration v2 and D1 migration 0074 both create the table and backfill every job's current definition as its first row — in D1 as an idempotent seed statement, the established way this plane carries data with a migration — so both residencies agree. #ceo-aimp
