### Added

- **Replay a past run (#4467):** from a Workflow Runs row, **Replay** starts a *new* run of the definition version that run executed, with that run's trigger — a new run id, new artifacts, and the original run and its artifacts untouched (`kind: "replay"`, `originRunId` = the run it replayed). The engine's `replayRun(jobId, runId)` reads the run through the seam it already records through, resolves the stamped `definition_version` from the history table (#5865), and dispatches through the **same** `executeRun` path as every other run — no second executor. Refusals are named, never guessed: an unknown run is `job_run_not_found`, a run that predates the stamp is `replay_pre_retention_run`, and a version that is no longer resolvable is `replay_definition_version_unresolved` — replaying "the closest version" would be a false reproduction. Reached through `POST /api/jobs/:jobId/runs/:runId/replay` behind the same operator gate as stage control, and not to be confused with `replayJob` (#4454), which re-enters the *same* run id after a workflow eviction. #ceo-aimp
