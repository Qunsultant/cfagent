### Added

- **Saved named nav presets, server-side (Qunsultant/cfagent#6151, S3):** the selection a user built in Settings can now be saved under a name and kept on the server (migration 0085: `agent_nav_presets` + `agent_nav_preset_state`, D1 + in-memory store ports behind `src/data/navPresetPorts.ts`). New routes under `/api/platform/nav-presets`: list + save (201, duplicate name is a 409), apply, rename, delete, and a selection write that persists manual toggles. The nav-availability endpoint reads the stored selection as its base (active saved preset, else the custom map, else the persona default) and gates it by subscription on every call, so a saved preset never resurrects a tab the caller's subscription gating removes; `availablePresets` now lists the built-in keys plus the caller's saved-preset ids. The settings page gains a Saved presets section (save form, apply/rename/delete, and a one-time offer to save the localStorage selection S1 adopted). Deleting the active preset keeps the current tabs — the selection becomes custom. A missing preset store degrades the nav read to the persona default and the list to empty; preset mutations fail closed with a 503.
