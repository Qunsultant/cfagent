### #6074: run the goal options leg on the options-pipeline nodes, retire the goal runner (6d-c)

- `goal.optionsLeg` now runs the eight options-pipeline stages (`options.runRoot` + `options.runStage` × 8: plan, chainFetch, enrich, screen, risk, persistCanonicalResults, shapeReport, deliver) in-process on the captured registry, with synthesized contexts scoped by the leg run id (`goal-screen:<engine run id>:options`); the leg defines its job first (`saveGoalOptionsLegDefinition` — the same definition record `JobPipelineControl.defineJob` persists, minus the control) and reads the screen artifact back (`readGoalOptionsLegScreen`). Both deps are bound in both host factories over the residency's job-pipeline stores. The nested dispatch (`runGoalOptionsLegViaWorkflow`) never runs on the engine path and stays only for the direct path until slice 7 retires it.
- The leg's request is the #4858 goal envelope verbatim PLUS the `goalRunId` stamp: the resolving steps rebuild the leg's ports per invocation from the stored request, and the goal shape's delivery builder is a pure function of the stamped goal run id — a goal-shape request without it refuses by name at the plan stage.
- Symbol resolution (owner rule 2026-11-22: never a symbol-less run, for ANY run): the leg resolves explicit `plan.optionsFilter.underlyingSymbols` when present, else the ONE shared externalized default as a universe stage input (`{provider: "nasdaq"}`, resolved by the factory — the input carries no universe name), else refuses by name (`GOAL_OPTIONS_LEG_NO_SYMBOLS`) — no leg-local literal. `DynamicOptionsScreener.fetchChains` no longer throws its symbols-or-maxUnderlyings validation for a discovery-mode leg constructed with universe deps (it now fires only when no symbols AND no `maxUnderlyings` AND no universeDeps).
- The `screener.goal` step's default runner is now the composition itself (`runGoalScreenComposition`): it synthesizes the analyze-node params the v2 builder writes (family job ids + market spec stage params + resolved symbols and shard table + `stockLegUniverse` when universe-fed) and threads the eight `goal.*` steps, returning the artifacts step's output. A test-injected `deps.goalRunner` still wins. `runGoalScreenOnEngine` is retired by deprecation (ledger entry 2026-11-22 in `docs/architecture/transition/deprecations.md`, `@deprecated` marker) — it stays, pinned, per gitops §22, like `runGoalScreen`.
- Tests: new `tests/goal_options_leg_generic_6074.test.ts` (9 tests: resolver, full run with no `runGoalOptionsLeg` call, symbol-less run on the default universe, leg failure as a failed class, old-style definition through the composition) and the 4192 default-bindings test re-pointed onto the real options leg (screens AAPL through the nodes).
