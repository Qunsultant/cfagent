### Changed

- **The hub's reads follow the broker selection (#3294, product-neutrality #3292):** `ETradeTradingHub` fetched `/api/etrade/status`, `/positions` and `/quote` directly, so an Alpaca tenant's hub read E*TRADE even though the Alpaca panel beside it did not. `src/client/brokerEndpoints.ts` now exposes `statusEndpoint`, `quoteEndpoint`, `positionsEndpoint` and `diagnosticsEndpoint`, and the hub uses them: E*TRADE keeps its exact routes, every other broker reaches the neutral reads added in #3293. Diagnostics are the deliberate exception — they read E*TRADE OAuth state and have no neutral equivalent, so `diagnosticsEndpoint` returns `null` for another broker and the hub renders a stated refusal (`"Broker diagnostics read E*TRADE OAuth state and are not available for the selected broker."`) instead of calling E*TRADE behind an Alpaca selection. After this change the hub contains no hardcoded `/api/etrade/status|positions|quote|diagnostics` path; a source pin fails if one returns. #ceo-aimp
