### Configure New Schedule: broker/mode shown once — dedupe to the one persisted selection (#5879)

- "⏰ Configure New Schedule" no longer shows broker and mode twice: the display-only #3655 Broker/Mode pair is gone, replaced by one tenant-default line ("Run target (tenant default): <broker> / <mode> (<data provider> feeds the data)") read from the one persisted tenant selection. The line states the live default and the fire-time re-resolution (broker and mode are re-resolved from Settings when the schedule fires; the effective mode is resolved again — deployment pin, tenant selection, or base-URL inference — and the run record states the mode that actually governed the run).
- For options schedules the #5189 per-schedule override stays, as closed #5187/#5189 require — now labelled "Broker override" / "Mode override", with a hint naming the tenant default it overrides ("Tenant default (Alpaca)"). The empty broker option finally names the tenant broker instead of reading "Tenant default (tenant default)": the form now passes the tenant broker id to the override fields (it never did — the prop was never wired).
- The Settings menu panel can no longer show an environment the server does not hold: the `localEnv` override is removed, and the panel reads the server-mirrored `useBrokerEnvironment()` value directly. A switch whose POST fails now reverts the panel (the hook value reverts); before, the local copy stayed pinned at the failed target. The `activeEnv` prop is retained for callers but no longer read as a source.
- No change to what broker/mode a run executes under; no new broker/mode state; no hardcoded broker names (labels come from `brokerPresentation`).
