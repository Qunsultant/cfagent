### Fixed

- **OODA fire hour is one declaration (issue #6030):** the scheduled research run's hour lived twice — the module literal `RESEARCH_SCHEDULED_FIRE_HOUR_UTC = 21` in `src/services/researchScheduleGuard.ts` and `researchJobConfig.scheduleUtcHour` (the documented `RESEARCH_SCHEDULE_UTC_HOUR` override). They agreed only by matching defaults, so setting the env var moved the guard window and left the fire decision behind: a 21:00 tick dispatched and the deterministic door refused `outside_guard_window`, then the 22:00 window found the day's run already burned. The literal is gone; `shouldFireResearchTick` (and `shouldFireStrategyBankTick`, same idiom) take the hour from `resolveResearchJobConfig(env)`, the same value `isWithinResearchGuardWindow` reads, and every dispatch path — the scheduled-tick route, the discovery rider, the strategy-bank rider — passes its resolved config. `NIGHTLY_RESEARCH_DISPATCH_CRON` becomes the derived `nightlyResearchDispatchCron(config)` and the Schedules home record reads the same resolved config, so the displayed cadence cannot disagree with the firing rule. Default behaviour at 21:00 UTC is unchanged. Pinned by `tests/ooda_fire_hour_single_source_6030.test.ts` (weekday matrix over hours 20–23 × `RESEARCH_SCHEDULE_UTC_HOUR ∈ {21, 22}`, plus the 21:00→`too-early` / 22:00→fire / second-tick→`already-fired` rows).
