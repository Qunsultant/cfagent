### Added

- **Options and trading mapped to what their runtime actually is (#3191, #3069 S6):** the trading flow's real durable steps are exactly two — `await-approval` (a `waitForEvent`) and `settle-trade` (a `step.do`); there is no fill or reconcile step, and the catalog had been listing both as if there were. `TRADE_APPROVAL_STEP_IDS` is now exported from `trading-trade-workflow` and declared as the trading stages' ids, with a pin that scans the flow and fails if the constant stops matching, plus a pin asserting no invented `fill`/`reconcile` ever returns. Options is a different case and now says so honestly: it is **not** a durable workflow at all — the request handler is the runtime — so `OPTIONS_SCREEN_PHASES` names its three real phases (`provider-screen`, `report-pipeline`, `deliver`) and a pin proves each phase still corresponds to a real call in that file. Five of seven families are now mapped to grounded ids; goal and strategy keep named gaps because they execute on another family's seam. 58 targeted tests green.
