### Uniform Copilot Standard S1: PortThink capability spine (#3489)

- **Capability manifest for every PortThink agent** (`src/actors/capabilityManifest.ts`): three families — channels {chat, webhooks, email, slack, voice} × runtime capabilities {mcpClient, scheduler, state, lifecycle, webSockets} × tools {workspace, sandbox, browser, webFetch, webSearch, aiSearch, payments, observability} — each entry `enabled` / `disabled-by-config` / `unavailable` / `not-implemented` with an evidence note. States are verified against the pinned SDK surface (agents 0.32.0 / @cloudflare/think 0.23.0) and repo evidence, never the docs alone: email/voice are `not-implemented` fleet-wide (S2/S3 land them), the sandbox is `unavailable` until a container backend is configured, webhooks are enabled at the port (#3474) but `unavailable` in any env without `THINK_WEBHOOK_SECRET`.
- **Externalized configuration (AOP, #2419 idiom):** doctrine defaults (enabled unless explicitly disabled) with per-agent overrides in `AGENT_CAPABILITIES_DISABLED` (`<class|binding|*>:<capability>`, disable-only — config never fabricates a capability, never masks a missing prerequisite; malformed entries surface as recorded config issues, resolution never throws).
- **Registry surfacing:** the manifest joins the S20 Agents view payload additively (`capabilitiesForClass` on `src/agents/registry.ts`; `capabilities` on each `MeshAgentView`), non-null exactly for PortThink entries. A fleet conformance suite (`tests/capability_spine_s1_3489.test.ts`) enumerates every PortThink subclass from the class inventory, cross-checks it against a source scan, and fails any class without an explicit, complete, truthful manifest.
