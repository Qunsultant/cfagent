### Added

- **One parameterized fundamentals job serves every universe, and every enrich job joins it (#3930, sub-issue of #3929):** the Yahoo fundamentals job (`yahoo-nasdaq100-fundamentals`) is generalized — its universe is now a run input (`universe`, naming the stored index list; default nasdaq100, kept for lineage) instead of a second job definition per universe, per the owner's Correction 2 (issue comment 6760544285). There will be no per-universe fundamentals jobs (the sp100/sp500/dow follow-up is cancelled). The run records the universe actually pulled; an unknown universe refuses by name (`FEED_UNIVERSE_UNKNOWN`) and a universe with no stored list fails `FEED_UNIVERSE_MISSING`, never an invented universe. Every quotes enrich job (Yahoo, Alpaca, E*TRADE, Public — every universe) now joins the parameterized fundamentals dataset for its own universe and carries the 14 fundamentals elements (values where the dataset carries the symbol, named gaps where it does not — the existing gap handling, never failures); the join is by symbol AND by universe, so one job persisting many universes into the same bucket never hands an enrich job another universe's copy. Each chain folds the fundamentals node in with the chain's universe as its input. Per-job opt-out stays behind `ENRICH_JOB_<JOB_ID>_FUNDAMENTALS_JOIN` (`auto`/`on`/`off`, default `auto`). The analyze "value" rule already reads `analystUpsidePercent` off persisted enriched rows, so the fundamentals surface in the cycle report with no new UX component. Known limitation: the feed status view for the fundamentals job shows the newest fundamentals artifact regardless of universe (the (source, dataset)-keyed read); the enrich join itself is universe-matched. #CISO-bhdm
