### Added

- **One broker parity matrix, enforced by a pin (#4038, #4039):** `docs/architecture/broker-parity-matrix.md` is now the single answer to "does broker X support capability Y, and if not why" — one row per capability (quotes, chains, accounts, positions, lots, preview, placement, cancel, history, watchlists, session orders) and one column per broker. Every cell is `parity`, `impossible (evidence)`, `live-only (reason)` or `—` for data-plane rows. `tests/broker_parity_matrix_4038.test.ts` reads the table and compares it to the three platform prototypes: a `parity` cell must be a real method, an `impossible` cell must be **absent** (so a stub returning empty data can never masquerade as parity), and every `impossible` cell must name its reason. The matrix records today's truths — Public has no lot read, no watchlists and no paper mode; E*TRADE has no session terms on the wire — instead of leaving them implied.
