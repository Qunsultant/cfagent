### Added

- Pay-per-run payment-intent resolution via the native ledger seam (related #2204): an approved pay-per-run refund now resolves its Stripe payment-intent id from the native ledger charge row (card rail only; gatewayRef, then proofSignature, then the note token) through a new `createPayPerRunPaymentResolver` in `src/services/refundPaymentIntent.ts`, wired as the second half of a composite resolver in the refund execute route only. A session-only row, a missing row, an x402 row, or a credit-only row still fails closed with the current unresolvable message — no id is ever guessed — and a resolved source whose tenant differs from the refund record's tenant is refused before any gateway call. Refund policy, crypto non-refundability, and the #2549 failure-credit XOR guard are unchanged.
