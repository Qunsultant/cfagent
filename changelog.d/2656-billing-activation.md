### Added
- Billing activation layer (issue #2656, Monetization Phase 2.1, sub-issue of #2405): subscription-mode Stripe Checkout mint route (`POST /payments/agentic/commercial/subscription/billing-checkout`, no row at mint), confirm-by-retrieve fulfillment route (`POST /payments/agentic/commercial/subscription/billing-purchase`: session complete + paid + reference match + metadata user/plan match + provider subscription/customer ids present + retrieved provider price id == operator-mapped price id + provider status active/trialing; replay → 409, customer-mapping mismatch → 409, otherwise 402), verified Stripe webhook application route (`POST /payments/agentic/commercial/billing/webhook`: unverified → 401, flag OFF → 200 flag_off, unknown ids/types → 200 not-applied, provider retrieve 404 → provider null, other retrieve failures → 503), and operator-only billing-policy routes (`GET/POST /payments/agentic/commercial/billing-policy`, not flag-gated). Billing customer mapping store (first-wins, D1 migration 0030 + in-memory adapter) so a second Billing checkout reuses the provider customer. Single-row `cancelSubscription` on the subscription store; the existing cancel route now provider-cancels Billing-managed rows (cancel-at-period-end) before locally canceling repurchase rows, atomically (any provider failure → 503, nothing canceled). `recordBillingSubscription` service function: idempotent provider-row recording from an already-verified provider subscription object.
- Activation only: plans, one-time checkout, and the Billing service are reused unchanged. The gate tier rule is unchanged; grace is NOT wired into the gate (PROPOSED policy only); the Subscribed included-run bypass stays OFF. No plan, price, or policy value is invented in code — plans are operator-created, prices operator-mapped, policy operator-set; a missing mapping refuses. Dunning-notice sending, immediate cancel, checkout UI, and expire/migrate migration are out of scope (later slices).
