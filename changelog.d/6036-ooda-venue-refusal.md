### Fixed

- **OODA research venue resolution refuses impossible pairs (issue #6036):** the run's broker × mode pair was resolved inside the provider with a cast, a free-string mode compared to one literal (`mode === "live"`, otherwise paper), and no catalogue check — so `public` + `paper` was accepted although that broker declares `paperMode: false`, a misspelt mode (`"Live"`, `"PROD"`, `" live "`) silently ran paper while the run recorded the requested string, and the `?? "paper"` default lived in the provider instead of the tenant binding. One resolver now decides the venue for every dispatch path (`src/services/researchVenue.ts`): the mode is normalised (trim + lower-case) and must be `paper` or `live` (`research_venue_mode_invalid`), the pair must exist in the catalogue (`research_venue_pair_unsupported`, naming `paperMode: false`), and an unregistered broker still refuses by name (`research_venue_broker_unknown`, #3460 preserved) — never a silent substitution. The provider executes the resolved pair (`this.venue`; no `?? "paper"`, no `mode === "live"` on the requested string) and the `/research/run` route refuses with a coded 400 before dispatch, so a rejected venue never reaches a run record. `modeSource` says whether the mode was explicit or inherited from the tenant binding. Pinned by `tests/research_venue_refusal_6036.test.ts` (catalogue-derived broker × mode matrix over `paper`/`live`/`Live`/`prod`, the `public` + `paper` refusal, the unknown-broker refusal, and source pins that no path bypasses the resolver).
