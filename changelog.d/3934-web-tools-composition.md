### Fixed

- **Web tools compose on every PortThink class, not only on the chat-turn hook (#3934, follow-on of #3494/#3495).** `web_fetch` and `web_search` were added to `PortThink.beforeTurn`, which fires only for a class that hosts a chat turn (`portHooks` set). `BrowserAgent` and `SandboxAgent` are headless — their port hooks are deliberately unset — so two capabilities their manifests reported `enabled` never materialized for them. `PortThink.getExecutionTools(base?)` is now the one composition seam: `beforeTurn` and a headless class's execution surface both route through it, so availability stays a manifest + resolver decision (`isPortCapabilityEnabled`) rather than a side effect of which composition mechanism a class happens to use. Additive only — a tool already on the surface, by its own name or as the MCP-discovered `tool_openaimp_<name>`, is never replaced or duplicated; the turn path's behaviour is unchanged. The `webFetch` / `webSearch` manifest notes for the base and for both classes now describe the composed reality.
