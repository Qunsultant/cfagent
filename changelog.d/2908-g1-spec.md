### Changed

- **StockScreenRunSpec completeness, G1 (#2908, under #2764):** the spec now carries trigger, userLogin, scheduleId (when scheduled), jobId, goalId (when goal), patternRef {patternId, version} pinned at run, and presetRef {presetId, resolvedAt} resolved at run, plus the existing fields. The broker reads jobId/userLogin/trigger from the spec (workflow trigger maps scheduled-only; the spec trigger rides the command as specTrigger), the planner derives its trigger from the spec, REST routes and the goal spec populate provenance, NLQ/mesh commands carry specTrigger, scheduled callbacks carry scheduleId when the payload has one, and the canonical body carries the spec fields. RunDetailView renders a missing trigger as "unknown", never as "scheduled". No screening semantics change, no deletions.
