### Added

- **Pareto frontier evaluation (#2773, under #2764):** stock-only deterministic dominance (at least as good on every objective, strictly better on at least one), as a post-screening DAG stage. New `src/workflows/paretoFrontier.ts`: `evaluateParetoFrontier` returns frontier + dominated set (each with dominators and per-objective gaps to the strongest dominator) + unscored set (missing/non-finite values named, never silently dropped); exact ties are co-frontier. No combined score anywhere — no weighted sum, no ranker disguised as Pareto. No automatic trading or promotion: the frontier is a view only. Stock stage `paretoFrontierForScreen` defaults to momentumScore + changePercent (both maximize); RSI is deliberately excluded (no RSI direction is inherently better — it stays a filter/gate); peRatio (minimize) is an opt-in extra objective. Wired into `ScreenerAgent.runScreenInner` (computed before persistence; additive `pareto` field on the run result, carried into the agent run store and the REST canonical body via the existing persist spread) with opportunities, ranking, delivery, and charging unchanged; failed runs carry no frontier. Capability inventory gains the pareto-evaluation entry.
