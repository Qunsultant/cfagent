### Added

- **Stock Copilot can cancel an order on any routed broker, not just the one it names (#5765):** the neutral, broker-routed cancel already existed as `POST /broker/order/cancel` — it resolves the tenant's selected broker, refuses a broker without the `orderCancel` capability **by name** (never asking another broker to cancel), runs Alpaca through the shared cancellation engine (`cancelSingleOrder`: bracket/OCO family and leg semantics, a filled order refuses) and every other broker through its platform adapter. The MCP surface only offered per-broker tools (`alpaca_cancel_order`, `etrade_cancel_order`, `public_cancel_order`), so "cancel my order" worked only when the caller already knew the broker. The new `broker_order_cancel` tool is that neutral surface: it takes an order id and **no broker** — the platform resolves it, which keeps one order on one broker and keeps "any broker" honest. It is synchronous (`SYNCHRONOUS_MCP_TOOLS`), gated as `mcp:trade`, requires the chat turn's acting identity, and records the cancel through the same `recordCancelOutcome` ledger path the route uses. Routing lives in one function (`cancelOrderViaSelectedBroker`) so the HTTP route and the tool cannot give different answers about one order. Replace (#5766) and preview/execute (#5767) are the family's next slices. #ceo-aimp
