### Added

- **Production stage checkpoint store over `mas_async_jobs` (#3027, follower of #2601):** `createAsyncJobStageCheckpointStore` reads one chain's rows through the queue port family (`ShardRow[]`, the same projection the planner uses) and returns the plan-shaped `StageRunnerCheckpoint` — so `planNext`/`resumeUnits` are usable without a bespoke query. The rows ARE the store: `write` refuses with a named reason (`stage-checkpoint-write-unsupported`) rather than creating a second unit table, an unavailable store returns `null` instead of an empty checkpoint that would read as "nothing ran", and a planned stage with no row is `never-attempted`. `checkpointFromChainRows` is the pure projection, pinned by `tests/stage_checkpoint_adapter_3027.test.ts` (6 tests). Nothing consumes the adapter yet — wiring is #3028.
