### Changed

- **Pattern apply pins patternRef, G2 (#2909, under #2764):** the Patterns tab Apply handoff now travels as URL params (pattern id, pinned version "1", filter, unmapped guardrails) that StockHub decodes into its New Screen criteria — fixing the audit F1 blank-form landing. A run with intact applied-pattern criteria sends patternRef {patternId, version} with the run request; the REST spec builder stamps it onto the spec and the canonical mas_reports body, the workflow command carries it, and replay shows it (object form, with legacy string refs still passing through). Guardrails with no filter field (e.g. trend_breakout volumeRatioMin 1.2) are shown as a qualification on the New Screen form, recorded as patternQualifications on the canonical body, and shown on replay and in RunDetailView — never converted into a filter, never silently dropped. Editing the criteria (or applying a preset) clears the applied pattern, so an edited run carries no patternRef. Patterns and presets stay separate; pattern apply never writes preset storage. No screening semantics change, no deletions.
