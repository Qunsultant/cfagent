### Added

- Unified run record for options strategy screens: `recordStrategyScreenRun` now stores the request as submitted (`input.*`, strategyMode, thesis, DTE window, risk profile, allowed strategies), provenance (jobType `options-strategy-panel`, submittedVia panel route, trigger), feed evidence (connector, dataSource, underlyingsScanned, contractsEvaluated, contractsMatched, fetchErrors, warnings, validationError), and a stage trace (feed, analysis, generation, delivery-skipped when no channel was requested) in the canonical `mas_reports` body. Docs Run Details reads the stored stages (recording derived from the written row) instead of rendering the request as unknown, and Workflow Runs overlays the same record onto its outcome twin by runId, so both views agree on scanned/matched/stage count/artifact statuses for the same run. A completed pipeline with 0 ranked surfaces `RUN_EMPTY_RESULT`, and a feed failed by provider fetch errors surfaces `RUN_PROVIDER_FETCH_FAILED`, using the existing Run Details catalog. Legacy runs without stored stages/input still render unknown, never guessed. No strategy selection, thesis filtering, caps, report content, delivery channels, scheduling, or connector behaviour changed.
