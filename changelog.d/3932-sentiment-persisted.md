### Added

- **One parameterized sentiment job persists sourced news sentiment, and every enrich job joins it (#3932, sub-issue of #3929):** the Yahoo sentiment job (`yahoo-nasdaq100-sentiment`) persists per-symbol news sentiment — up to 5 Yahoo News headlines per symbol (from the same `v1/finance/search` feed #132 reads), classified per headline by the existing batched LLM classifier (`classifyNewsSentiment`, #132, with #881 instruction/data separation) and aggregated per symbol (mean of +1/0/-1, bullish at >= +1/3, bearish at <= -1/3, else neutral; score rounded to 6 decimals) — one job definition, parameterized by universe (its universe is a run input naming the stored index list; default nasdaq100, kept for lineage), per the owner's Correction 2 on #3932 (issue comments 6760487336, 6760547214). The Yahoo adapter now declares the `news` capability (the conformance kit's `checkNews` covers it); a provider without it refuses with `FEED_PROVIDER_NEWS_UNSUPPORTED`, and a symbol with no news is skipped, never zero-filled. Without an AI binding a row still persists with method `unavailable` and a null label — news fetched, assessment honestly absent, never a guessed label. Every quotes enrich job (Yahoo, Alpaca, E*TRADE, Public — every universe) now joins the parameterized sentiment dataset for its own universe and carries `sentiment` (label) / `sentimentScore` / `sentimentSource` / `sentimentMethod` / `sentimentModel` where the dataset carries the symbol; a missing sentiment copy is a named `requires_sentiment_dataset` gap and a partial run, never a fabricated value, and a missing symbol is a named per-symbol gap while an unclassified row is a named `sentiment_unclassified` gap. Each chain folds the sentiment node in with the chain's universe as its input (feed → fundamentals → technicals → sentiment → enrich → analyze → generate → deliver). Per-job opt-out stays behind `ENRICH_JOB_<JOB_ID>_SENTIMENT_JOIN` (`auto`/`on`/`off`, default `auto`). The price-derived heuristic is renamed `dayAction` (in `ScreeningIndicators`, the screener rows, and the enrich screening elements) so it is never presented as sentiment: the screener UX now shows the sourced sentiment (or "—" for gaps) in its Sentiment column with its source on hover, alongside a separate Day action column, and the PDF/CSV/XLSX reports render the sourced label or "-" instead of the old `?? "neutral"` default. #CISO-bhdm
