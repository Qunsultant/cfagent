### Fixed

- Options F1 auth guard (#2599, F1 only): the manual panel routes (`POST /trading/options/strategies`, `/best-trade`) previously scanned with no preflight, so a dead/expired E*TRADE token failed mid-scan with a raw broker error. They now apply the scheduled-run verify → renew → block policy before any scan (`panelAuthResponse` in `src/services/optionsAuthFreshness.ts`, reusing `etradeAuthPreflight.ts`): a blocked run returns a catalog-coded 401 (`FAILURE_AUTH_TOKEN_EXPIRED` / `FAILURE_AUTH_NO_SESSION`, no new catalog entries) and no scan runs. The one-alert-per-episode behaviour is preserved — the manual guard sends no additional alert (the synchronous 401 is the notice to the signed-in caller); scheduled runs keep their single episode alert. A new chain-freshness probe labels every panel snapshot from its scan timestamp (fresh / stale when older than the documented 15-minute default / unknown when the timestamp is missing), derived in the record layer (`recordStrategyScreenRun`, from `screen.scannedAt`) and carried on the unified run record's feed evidence, so stale chains are never presented as live — the documented degraded mode. The route call itself is deliberately terse (one import, two lines) because `etradeOptions.ts` sits just under the #359 50 KB ratchet; the reasoning lives in `panelAuthResponse`'s docstring, and no probe code lives in the route. No provider fallback is added: options chains are never Yahoo-substituted (the Yahoo adapter declares quotes/bars/fundamentals only, no `optionsChains`) and no selection, ranking, pricing, flag, or delivery behaviour changes. F2–F8 ship in the same #2599 branch (see changelog.d/2599-failures-f2-f8.md).
