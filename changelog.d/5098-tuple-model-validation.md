### Added

- **Account binding tuple model, validation seam & migration (#5098, Slice F1 of #5094):** enforced the 4-element binding `{ broker, mode, accountType, accountId }` (`AccountBindingTuple`) across tenant state and per-surface scopes (`tenant`, `autopilot`, `copilot`, `schedule`, `ux`, `audit`). Added `validateAccountAgainstBroker` to validate proposed bindings against actual broker accounts with fail-loud coded errors (`FAILURE_ACCOUNT_UNKNOWN`, `FAILURE_ACCOUNT_UNOWNED`, `FAILURE_ACCOUNT_ASSET_TYPE_MISMATCH`, `FAILURE_ACCOUNT_BROKER_MISMATCH`, and `FAILURE_ACCOUNT_BINDING_MISSING`), completely eliminating silent fallbacks. Added `migrateLegacyBrokerSelectionToTuple` with an unambiguous default-account rule (single candidate or explicit default migrates cleanly; multiple accounts fail loud with `FAILURE_ACCOUNT_MIGRATION_AMBIGUOUS` so the tenant is asked instead of guessed). Exposed validation and migration via `src/services/accountBindings.ts`, the `/broker/account-binding` API, and the `broker_account_binding` MCP tool.
