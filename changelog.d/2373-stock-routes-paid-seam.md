### Added

- Manual E*TRADE and market-data stock screens now follow the same payment path as goal screens (#2373 Slice A): under monetization ON, `POST/GET /etrade/screen` and `POST/GET /market-data/screen` (plus `/foss/screen`, `/yfinance/screen`) route through the existing paid-screen seam to the payment workflow (family `stock`, trigger `manual`) instead of running a free screen, answering `202 { runRequestId, workflowId, status: "payment_started" }`; sync requests under monetization ON are refused with the goal route's `402 monetization_enabled_workflow_required`, and a payment-workflow start failure answers `503` with no run started. Flag OFF behavior is unchanged (broker-or-sync, including broker-null fallthrough). The spec-to-parent-command mapping is extracted as `buildStockScreenWorkflowCommand` in `screenExecutionBroker.ts`, shared by the broker and the new `paidStockScreenSeam.ts` helper; the `listings` branch is untouched (it returns before spec building, so it never reaches the payment stage). No price logic added: the workflow gate checks prices internally, including price-approval state.
