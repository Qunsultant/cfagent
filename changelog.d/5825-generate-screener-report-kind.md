### Added

- **Generic generate produces the screener-report kind (#5825, #4437 slice 4):** the generate family gains a second report kind, `screener-report` — the screener's report shape over the persisted analyzed artifact (market-screen title and summary, opportunities as top by composite, screened symbols with their verdicts, gaps), rendered in json/markdown/csv/pdf and stored through the canonical leg (#3940) where a host wired it. The kind is opt-in per job (the `REPORTS` knob or the `generate.apply` step params); the built-in default stays `analysis`, so no existing generate job silently gains a second report. Parity with the bespoke screener report is pinned by `tests/generate_screener_report_5825.test.ts` on the fields the analyzed artifact carries (same symbols, prices, scores, counts, opportunities). Explicitly not parity: the bespoke report's rich per-symbol fields (RSI-14, MACD histogram, P/E, company, sector, sentiment, factor grades) and the matched count are not in the analyzed artifact and are not in this document — closing that gap is analyze/enrich schema work, outside this slice. #CAIO-quns
