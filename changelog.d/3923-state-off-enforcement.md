### Added
- State-off enforcement at consumers (#3923, follow-on of #3741): the capability manifest's requires-edge refusals (`capability_requires_state:<id>`) are now acted on at the shared PortThink composition choke points, so every subclass inherits the enforcement. Scheduler arming refuses by name: PortThink overrides the SDK `schedule`/`scheduleEvery` methods — the funnel for the ActorSchedulePort facet, the classes' inline facets and direct loop starts, the NLQ execution port, and Think's declared-task arming — and throws `PortCapabilityRefusalError` (code `capability_requires_state:scheduler`) before the SDK persists anything on a fully ephemeral instance (state disabled by config). The workspace port returned by the base is guarded the same way (every method refuses `capability_requires_state:workspace` before touching storage — one wrap covering the turn tool builder, the /workspace HTTP channel, and the actor-port facet), and the HTTP channel refuses in its own idiom (403 JSON naming the refusal, before the lifecycle boot). PaymentsAgent's execution entry (`processPaidRequest`, which the A2A dispatch funnels through) asserts servability and refuses `capability_requires_state:payments` before any guard or ledger work. Stateless work is untouched: with state off, web tools and turns run with zero Durable Object storage contact on the enforced paths, and production posture (AGENT_CAPABILITIES_DISABLED empty) carries no refusals — every enforced path delegates byte-identically to before.
