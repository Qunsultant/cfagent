### Added

- **The Slack credentials reach the deployment (#3974).** Seven Slack GitHub secrets existed in the Environment and none reached the Worker: `deploy.yml`'s secret sync never pushed a Slack name, so a Slack webhook, bot token or signing secret set in GitHub changed nothing at runtime. The four names the code actually reads — `SLACK_SIGNING_SECRET` (inbound request signing), `SLACK_BOT_TOKEN` (bot-API delivery), `SLACK_CLIENT_ID` / `SLACK_CLIENT_SECRET` (the `/slack/install` + OAuth callback pair) — are now pushed from their existing GitHub secrets as `optional_secret`, so an absent value is reported in the job summary and leaves the channel fail-closed rather than failing a code deploy. The three names no code path reads (`SLACK_APP_TOKEN` for Socket Mode, the deprecated `SLACK_VERIFICATION_TOKEN`, and `SLACK_APP_ID`) are deliberately **not** synced — wiring them would configure a capability the Worker does not implement — and `docs/architecture/security/api-security.md` §7 records each reader, what absence means, and what would have to change first.
