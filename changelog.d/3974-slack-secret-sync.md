### Added

- **The whole Slack credential set reaches the deployment (#3974).** Seven Slack GitHub secrets existed in the Environment and none reached the Worker: `deploy.yml`'s secret sync never pushed a Slack name, so a webhook, bot token or signing secret set in GitHub changed nothing at runtime. All seven — `SLACK_APP_ID`, `SLACK_APP_TOKEN`, `SLACK_BOT_TOKEN`, `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, `SLACK_SIGNING_SECRET`, `SLACK_VERIFICATION_TOKEN` — are now pushed as `optional_secret`, so an absent value is reported in the job summary and leaves the channel fail-closed rather than failing a code deploy, and enabling a channel later needs no second deploy change. Five have readers today (signing secret, bot token, client id, client secret, webhook URL); the other three are staged for a reader that does not exist yet — `SLACK_VERIFICATION_TOKEN` is deployed for completeness only and must never become a second inbound verification path beside request signing. `docs/architecture/security/api-security.md` §7 records, per name, the reader, what absence means, and the staged status.
