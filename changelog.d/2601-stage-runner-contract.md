### Added

- **Stage-runner contract for every screen invocation mode (#2601, under #2528; sequenced by #2621):** the one plan/checkpoint contract the three consolidation seams will move onto — `StageRunnerPlan` over the existing `StageName` vocabulary with per-stage execution/timeout and `pipelinePolicy`-resolved retry buckets (`resolveStageRetryBudget`), `planRun`/`planNext`/`resumeUnits` (a resume re-runs only units that did not complete), capped fan-out that names its deferred tail (`fanout_cap_exceeded`, never a silent truncation), and `checkpointFromStageRows` projecting `mas_async_jobs` stage rows onto one entry per planned (stage, unit) pair with `never-attempted` for a stage that recorded nothing. Seams named for the follow-on PRs, one each: `src/services/shardJobs.ts` chain planner (`planShardAdvance` et al.), `src/agents/orchestrator/asyncJobs.ts` DO-alarm scheduler, `src/workflows/screenerWorkflowFlow.ts` poll loop. Contract only — no execution path is wired, moved, retired, or changed; deterministic mode stays the default and the #2530 ND gate stays off. Recorded in ADR 0027 and `docs/architecture/business/options-stage-runner-contract.md`; pinned by `tests/stage_runner_contract_2601.test.ts`.
