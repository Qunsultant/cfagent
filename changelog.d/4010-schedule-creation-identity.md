### Fixed

- **Schedule creation acts as the signed-in owner, not a stale instance context (#4010):** creating any account-scoped schedule failed with `CONNECTION_NOT_BOUND: no credential: connection alpaca:TEST:openaimp has no stored credential for this login`, and the live/paper switch changed nothing because the environment was pinned to `TEST`. `POST /api/schedules/create` resolved `context?.userLogin || headerUserLogin` — the per-instance screener context outranked the Worker-verified `x-user-login`/`x-environment` of the request, so the credential preflight ran against the wrong connection. The header is now authoritative whenever it is usable, the stored context is the fallback for callers that carry no identity, and a malformed header falls through instead of acting as one. Pinned by `tests/schedule_creation_identity_4004.test.ts` (4 tests: header wins, context fallback, malformed header ignored, configured-environment fallback).
