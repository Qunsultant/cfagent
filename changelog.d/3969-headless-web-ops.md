### Added

- **Web tools realized on the A2A operations surface for the headless agents (#3969, Route A of #3934).** `BrowserAgent` and `SandboxAgent` host no chat turn, so the `web_fetch` / `web_search` capabilities their manifests report `enabled` were never served on any production path: PR #3942 composed the tools onto `PortThink.getExecutionTools`, whose only production caller is the chat-turn hook. Both classes now serve the capabilities where they are actually invoked — new A2A operations `browser.web_fetch`, `browser.web_search`, `sandbox.web_fetch`, and `sandbox.web_search` (dispatch sets and agent cards updated together, OASF skill mappings added) — executed through new `fetchWeb` / `searchWeb` class methods that call the same services as the turn path (`src/services/webFetch.ts`, `src/services/webSearch.ts`) behind the same capability gate (`isPortCapabilityEnabled`): a capability withdrawn by `AGENT_CAPABILITIES_DISABLED` refuses by name (`capability_disabled`) before any service call, and service failures surface their named `web_fetch_*` / `web_search_*` codes, never fabricated content. Conformance is pinned at the dispatch level in `tests/headless_web_ops_3969.test.ts` (through each class's `handleA2A` with the real bound executor and a stubbed fetch). This completes #3934: the manifest claim now matches the served reality.
