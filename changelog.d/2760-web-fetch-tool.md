### Standalone `web_fetch` MCP tool (tracker #2708 A3)

- The openaimp MCP catalog gains `web_fetch` (mcp:read; catalog 84 → 85, composed on #2731's web_search landing): fetch one URL with a plain Worker fetch and return its readable text — title plus body text for HTML, extracted with the same `stripHtmlToText` extractor BrowserAgent's fetch fallback uses; raw body for plain-text/JSON responses. The result names the final URL after redirects, the HTTP status, the content type, and a `truncated` flag when the hard limits (30s max timeout, 2 MiB body cap, 20,000-char text cap) cut content. Non-2xx responses, unsupported content types, invalid or non-http(s) URLs, timeouts, and network failures fail with named `web_fetch_*` errors — content is never fabricated. The registry `web-fetch` tool family flips from `absent` (S14 #2417) to `live`, owning the new command; rendered-page surfaces (screenshots, DOM tables, snapshots) remain BrowserAgent's.
