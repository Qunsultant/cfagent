### Changed

- **E*TRADE runScreen-throw failures now persist-then-deliver, G5 (#2912, under #2764):** when the single-run screen throws instead of returning a failed result, the route fabricates the failed-run shape a returned failure carries (zero counts, empty sets, the thrown error, trigger manual) and runs it through the #2861 persist-then-deliver finalizer with the same persist + deliver definitions the success site uses — so a thrown failure writes exactly one canonical `mas_reports` row (generationId dedup means a retry never creates a second row) and one failure notification, in that order, and the row reads back as a failed Reports row with the error in its summary. The throw still propagates, so the route contract is unchanged; "already running" still short-circuits to 429 with no persist and no notification (#832). The finalizer's former known-exception note is updated to record the closure. Follow-up, explicitly out of scope here: a `runSharded` rejection (one shard throwing under `Promise.all`) still propagates without persist or notification — it needs per-shard attribution before it can be finalized the same way.
