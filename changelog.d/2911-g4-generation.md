### Changed

- **One stock report generation path, G4 (#2911, under #2764):** PDF, XLSX, and CSV for a stock run now all flow through one generation module (`src/services/stockReportArtifacts.ts`) — PDF via the unified report pipeline as before, XLSX/CSV via the trading generators under the report retry policy, stored per-run plus the latest pointer. `ScreenerAgent.persistRun` (PDF via the shared regeneration path, tabular legs via the module) and the shard executor's stock tabular leg both route through it; the stock generators are called from exactly one place in `src/` outside their trading definitions (pinned by test). The private `generateRunCsv` agent method is retired, superseded by the module's CSV leg. One shared status vocabulary (`src/services/stockReportFormatStatus.ts`: generated / failed / missing / never-attempted / skipped) now backs the writers, the workflow parent row, and the client: a failed leg renders its coded error, a never-attempted or skipped leg says so, and only a genuinely missing leg says "no record". RunDetailView gains the CSV artifact row; ReportsPanel gains XLSX/CSV unavailable notices mirroring the PDF leg. No report content change, no deletions, no options-domain change (options tabular legs keep their own generators).
